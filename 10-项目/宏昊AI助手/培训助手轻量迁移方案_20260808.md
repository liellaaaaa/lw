# 培训助手轻量迁移方案（2026-08-08 定稿）

## 一、背景与定位

- 培训助手当前依附于宏昊AI助手平台（供应商系统），学员经企业微信 bot 进入其内置「学习中心」学习、考试、看报表。
- 轻量迁移定位：**后台不迁移，保留在宏昊AI助手**。只做两件事：①通知 Bot 独立（发通知与跳转目标改造）②选修浏览重设计（宏昊学院 UI）。其余培训模块功能仍走宏昊AI助手后台。
- 目标：简化方案、降低供应商改造量，9月前完成问题闭环与功能迁移（7-31 团队对齐会决议）。

## 二、六大块定稿（与培训主管对齐）

### 1. 报表改造（单表 + 3 列）

- **现状**：「总培训数据报表」22 列，必修口径（完成度/完成率/逾期/考试完成率，分母=应指派完成数）。选修无"应完成"概念，只能进"量"不能进"率"。
- **决策**：
  - 报表不改名、不拆表；必修 22 列口径不动
  - 末尾新增 3 列：选修学习时长(小时) / 选修考试通过率(%) = 及格考试数 ÷ 参与考试数 / 总学习时长(小时) = 必修 + 选修
  - 加筛选「课程类型：必修 / 选修 / 全部」，默认必修
- **关键前置（现在必须跟供应商确认）**：学习行为上报接口、获取个人学习数据接口的出入参必须带 `course_type` 字段，否则二期做不了。

### 2. 选修翻必修（清零重置模型）

- **决策**：翻成必修后，学员**直接重看 + 重考**；系统按学习发生时的课程类型自动写入对应桶（必修桶 / 选修桶），不跑翻转时达标校验。
- 必修桶：时长 / 通过率 / 完成率一律从 0 开始（清零重置）。
- 选修桶：保留历史值不动。
- 总学时 = 必修 + 选修，天然为两次真实学习行为之和（翻转前=选修、翻转后=必修重看），允许同一内容出现两次，**无需 dedupe**。
- 主管接受的代价：劝退主动学习者（需重看）、总学时重复算——均判为可承受成本。

### 3. 通知 Bot 迁移

- **当前**：培训计划下发 → 宏昊AI助手 bot 推送卡片 → 点进宏昊AI助手「学习中心」。
- **目标**：培训计划下发 → **培训助手 bot** 推送同样卡片 → 点进**培训助手自己的学习页**（不再走宏昊AI助手）。
- **迁移范围**：仅通知发送方 + 链接目标改造，后台不动。
- **接口要求**：消息通知接口（接口 6）建议带 `course_type`。

### 4. 每周一 09:00 汇总提醒

- 培训助手 bot 每周一定时推送本周学习汇总，5 类计数：本周需完成 / 已完成 / **仅学未考** / 未学习 / 逾期未完成。
- 依赖：定时任务 + 学习数据接口（需 `course_type`）。

### 5. 学习 / 考试进度条分离

- 必修卡片原单条进度条（100% 即完）掩盖"学完没考"风险。
- 改为两条独立横条：学习进度（默认色）+ 考试进度（橙色）。
- 空状态（无考试）隐藏考试条。

### 6. 宏昊学院（选修）UI

- 取消标签筛选（二级目录数量有限、未来不频繁新增，无需第二筛选轴）。
- 模型：根节点唯一（宏昊学院）+ 子级全部同级 + 树深度 N 层（实测 3-4 层）+ 每层「子目录 + 文件」混排。
- 命名定稿：宏昊学院（选修），不带"凑学时"。
- 视觉：课程卡片 / 分类区块范式，非 Windows 文件管理器混合视图。

## 三、关键决策边界（踩坑记录）

- **量率分流根因**：必修有"应完成/截止"，走率类（完成率/逾期/考试完成率）；选修无指派，只能走量类（时长/通过率）。22+3 两摞列正是此因。
- **原子判定 vs 聚合口径**：某人是否达成学习目标（原子层）与课程类型无关可共用；但报表聚合口径（必修分母 vs 选修量）不能共用 → 分列。
- **翻转强制回填（初版，已被主管改为清零重置）**：最初建议翻转时对着新必修目标做达标校验、已达成者免重看；主管拍板改为"直接重看重考 + 清零重置"，模型更简单、供应商实现更少出错、必修分母干净。
- **course_type 是前置硬依赖**：学习行为记录必须带课程类型，才能区分选修/必修时期产生的小时，否则翻转只能洗数据。
