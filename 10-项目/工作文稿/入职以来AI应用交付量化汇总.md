# 入职以来 AI 应用交付量化汇总（2026-04-15 入职 ~ 2026-07-31）

> **统计窗口**：2026-04-15（入职）~ 2026-07-31。2026-01-01 ~ 04-14 为入职前，无相关产出，如实标注"未入职"。
> **8 月收尾**：2026-08-01 ~ 08-07 为交付收尾期，关键项（Tax_check 08-01 交付运营、Data_masking v1.2.0 08-07 迭代）并入对应章节并标注「收尾」。
> **数据来源**：本知识库 74 篇日报、16 周报、3 份月报、2 份项目日志、4+ 批次验收/问题反馈汇总、项目索引（GitHub 实时同步 08-06）。
> **岗位本质**：AI 技术专员 = 出方案 / 判断方案 / 对接领导一键 / 推动执行与迁移，**不是运营**（2026-08-08 校正）。本报告据此把"方案设计、验收监督、推广采纳"单列，不被"执行"吞没。
> **本报告每节均含「价值结论」，先讲解决什么业务问题，再给数字。**

## 〇、工作框架总览（内外两部分 · 复盘骨架）

> 本复盘严格按"内 / 外"两条线展开。内部靠自研与赋能，外部靠供应商平台验收与运营。

**内部（公司内）**
1. **需求研判 · 方案设计 · 跨部门对接** — 从"接需求"前移为"判需求、出方案、对接领导拍板、推动执行与迁移"；需求来源 = 运营收集回流 + 跨部门直接对接。
2. **自研应用交付（建应用路径）** — 客户端 / 前端 / 前后端程序，如船务 TT 助手、采购分析助手、纯前端对账单、退税审单、数据脱敏。
3. **Skill 抽象与复用（提效路径）** — 复现他人工作场景、抽象输入输出为可复用 Skill，提效或赋能业务自建。
4. **培训与推广** — 技术（编程 / 前后端 / Skill 详解）+ 非技术（WorkBuddy / 千问办公 / minimax code / 读书分享）；含采纳驱动与内部宣推。

**外部（供应商）**
1. ~~找供应商实现固定需求（线索获取等）~~ — 非重点，本复盘不展开。
2. **宏昊 AI 助手平台（供应商）** — 验收运营与质量闭环、知识库内容运营监督、权限与文档管理中心、各智能体、培训助手、内容生成助手（视频/图片）。

## 二、内部工作一：需求研判 · 方案设计 · 跨部门对接

**定位**：岗位本质层——把"接需求做执行"升级为"判需求、出方案、对接领导拍板、推动执行与迁移"（2026-08-08 校正：不是运营）。

| 动作 | 说明 | 量化 |
| --- | --- | --- |
| 需求研判 | 拆解运营回流 + 跨部门直提需求，判断可行性与优先级 | 覆盖全部 5 个自研应用 + 4 个平台智能体 |

**定位**：财务部出口退税「资料齐全性体检」工具，已于 08-01 打包交付运营（收尾并入）。

| 指标 | 数值 | 备注 |
| --- | --- | --- |
| 角色 | 全栈开发 + 产品交付 | 由本人独立承担，非供应商平台 |
| 最新状态 | ✅ 已交付运营 | 08-01 打包交付；08-03 OCR 重命名 + 接口重构 + 多项修复 |
| 架构演进 | FastAPI（08-01 迁移） | 从纯静态 HTML+JS 迁移至 FastAPI 架构 |
| 技术栈 | FastAPI + RapidOCR（OCR）+ pdfplumber/pypdf（PDF 解析）+ PyInstaller 打包 .exe |
| 数据合规 | 本地 .exe 运行，数据不出境 | 满足财务敏感数据不出境要求 |
| 关键提交 | 08-03 feat: OCR 重命名 + 确认接口重构；08-01 feat: 迁移 FastAPI + 图片/扫描件 OCR + .xls 支持 | — |

**功能要点**：文件名关键词 + OCR 内容识别自动判定单据类型；按价格条款（EXW/FOB/C&F/CIF）矩阵判断必传单据是否齐全；双击改名重新匹配、图片/PDF 预览、确认后一键导出规范 ZIP；LLM 智能审核（P2）待规划。

**价值结论**：外贸出口退税命门是「资料齐全且规范」——一笔业务需备齐 16+ 种单据，且按价格条款不同必传单据不同。原靠财务人工在几十上百份文件里逐一核对，慢、易漏、新人上手难。工具把"资料齐全性体检"自动化——OCR 识别+重命名、条款矩阵判定、一键导出规范 ZIP，把财务从"肉眼翻几百文件找缺什么"变"工具 1 分钟告诉你还差哪张单"。
