# SDS编写-升级版（纺织助剂 SDS 端到端编写流水线）

**日期**：2026-09-10 归档

> **一句话**：给配方 → 启动弹窗一次采集齐 → 四段人工确认（模板/ECHA 结果/汇总确认表/填充前放行）中间一路自动算 → 填 docx + 三遍自审 + 内容 MD5 三连一致 → 交付。

## 版本演进（重要）

- **桌面 `SDS/SDS编写-升级版`（09-07）是旧迭代**：逐项人工确认流程，每次填写都被打断。
- **skills 内版本（09-09）是现行版**：四段式确认 + **自包含**（6 份占位符模板三公司×中英文 + 9 张 GHS 象形图 + 本地 ECHA 精简库 198MB/40 万 CAS 中英双语随包走，可由 21MB 源数据 8 秒重建）。以 skills 为准，桌面是历史存档勿改。

## 流程纪律（两次实战复盘的核心）

1. **Step 0 开场采集**：AskUserQuestion 一次问齐 名称/配方(含水的处理)/物理状态/颜色+pH；解析结果先复述成表核对；配方合计≠100% 当场指出（唯一允许的 Step 0 追问）。
2. **确认只有 4 段**：①模板必问（即使能猜到也必须列 6 选项，禁止默认）②ECHA 查询结果过目（查不到的当场处理，不许带疑问进 Step 3）③Step 3-8 自动算完给汇总确认表（小歧义标「待确认」一次定，**禁止逐步打断**）④填充前放行。
3. **水的口径不固化成规则**：HT-8077（水 47%）不计入 S3 走附注；WET ST600（水 7%）计入 S3——每次以用户当次选择为准，写入项目说明备查。
4. **产出纪律**：Skill 目录是只读程序资产，docx/spec/校验报告/项目说明一律放当前工作区项目文件夹；不做历史项目回顾、不自动沿用上次配方。

## 填充引擎与自审（R37-R42 + 十项必查）

- 占位符精确匹配 `{{KEY}}` 不走 smart_match；P 短语键必须带 `S2.` 前缀；`CAS_9` 第一段补零到 **7 位**；`row.cells` 取不到 `<w:ins>`/`<w:hyperlink>` 内 run 要用 XML 迭归。
- 象形图固定 `Cm(2)×Cm(2)`；无分类时**宁可删行不留重复行**；删表前先锁存表元素引用防表号漂移。
- 三遍自审：10 项必查（残留 `{{`=0、英文版无中文、行数、Weight% 合计 100%、P310 存在性、象形图尺寸、跨章节成分一致、无残留蓝色、内容 MD5 三连一致）。
- **高频踩坑全录**（9 条）：只替换 KEY 不替换花括号、前缀缺失静默不替换、vMerge 单元格错位、删行顺序 IndexError、预览锁文件改 v1.1 输出等——两次实战全部踩过。
