# 异常报告填写 · 厂内质量异常报告自动化 Skill

> **对接部门**：制造中心体系部（需求方 苏永生）
> **状态**：✅ Skill 已开发完成并交付试用。2026-09-03 一天完成「案例库本地化 → 脚本修复 → 表单改版 → 端到端验证 → 落库安装」闭环，09-04 修复勾选 bug + 表单升级 v4 + 两份真实单据实战归档，当前进入真实单据试用与推广期。
> **一句话**：**填写人只填「事实」，AI 只补「分析」**——网页表单收集 ①～⑤ 人工项，AI 生成 5why / 根本原因 / 暂定对策(a) / 恒久对策(b)，脚本自动填入 QR-260D 模板并回读校验，输出 docx 并归档进案例库。
> **成本**：一份报告约消耗 50 积分，平台登录赠送 2000 积分 → 日常用量足够（09-04 与苏永生确认）。

## 项目简介

面向宏昊化工制造中心《异常报告书》（**QR-260D，TD01 第1版**）的填写场景。AI 只补齐三块内容：**5why 分析 + 不合格根本原因 + 暂定/恒久对策**；其余（判定单位区、部门/签名/日期）一律留空，由人工/结案人填写。

区别于以往工具型项目：本项目**没有独立仓库，以 WorkBuddy user-level Skill 形态交付**（`~/.workbuddy/skills/异常报告填写/`），模板/脚本/案例库随 Skill 走，无桌面路径依赖。

## 需求背景与价值

- **痛点**：异常报告人工填写耗时长；5why 与暂定/恒久对策质量参差，常写空话；历史案例经验（70+ 份档案）沉淀在文件夹里，写新报告时检索不到、复用不上。
- **方案**：把 71 份历史异常案例做成 Skill 自带案例库，按「品名 / 异常类型（糖度/粘度/外观/pH）/ 设备（釜/槽/泵）/ 现象关键词」检索相似档案，参考其「原因分析 + 处理措施」口径生成对策——把老师傅经验固化进 AI 输出。
- **效果目标**：待量化（已请苏永生提供正常填写一份报告的基线耗时，用于提效对比）。

## 运行流程

```
S1 信息收集① ──► S2 信息收集② ──► S3 草稿生成 ──► S4【阻塞】确认 ──► S5 脚本填写 ──► S6 校验+归档
 异常描述+发文单位   5M1E+主要原因   5why/根因/对策     用户确认草稿     fill_report.py   回读校验+A-*.md
```

- **推荐入口**：填写人打开 HTML 表单只填 ①发文信息 ②勾选项 ③产品信息 ④异常描述 ⑤人机料法环测信+主要原因 → 复制 JSON 回传 → AI 直接执行 S3-S6（**5why 与对策始终由 AI 生成**，表单不收集）
- **S3 案例检索**：Grep 案例库取最相似 1-3 份，参考其「三、原因分析 / 四、处理措施」写法；检索不到则按通用质量逻辑生成并标注
- **S6 归档**：新案例写入 `异常案例库`（tdrive）+ 本地副本，编号顺延（`A-{流水NN}-{季度}-{年份}-{季内序号NNN}`），同步更新 `25-26异常案例档案索引.md`

## 关键规则（硬性）

| 编号 | 规则 |
|---|---|
| R1 | **阻塞节点**：S3 草稿未经用户确认，不得写文档 |
| R2 | 判定单位区、部门/签名/日期一律留空，脚本不写 |
| R4 | 暂定/恒久对策整段重写，模板占位符（`xxx`）清除干净 |
| R5 | 只填指定位置，保留模板原字体/线框/版式，不改结构 |
| R7 | 配方等保密信息不外传；归档 A-*.md 带 🔒 与保密 frontmatter |
| R8 | 输出必须过 `verify`（`ok=true`）才可交付 |
| R9 | 收到表单 JSON 立即执行 S3，不得反问用户"需要做什么" |
| R10 | **5why 不强制 5 层**，问到可验证根本原因为止；占位符整段替换严禁 append |

## 技术要点

- **模板定位**：模板大量 `gridSpan/vMerge`，`row.cells` 会错位，必须用 `tr.findall(w:tc)` 索引（脚本 `cell_at` 已封装）
- **格式保留**：追加文本挂在已有 run 上（`append_text`）；整段重写只保留首 run 格式
- **勾选符号**：模板中「厂内质量异常」「首次异常」「第  次异常」前**无 □**，勾选时需补 ☑（09-04 修复的坑）
- **JSON 契约**：正文禁用 ASCII 双引号（用「」），`whys` 的 q/a 不带 `WhyN：`/`答：` 前缀
- **校验**：`verify` 共 42 项（含 R10 全局 `xxx` 残留拦截）
- **Python 环境**：WorkBuddy 托管 venv（`~/.workbuddy/binaries/python/envs/default/Scripts/python.exe`，已装 python-docx）

## 已知问题与风险

- **双副本一致性**：本地 Skill 目录与 tdrive 资产是两份独立副本，改版须同步（已踩：v3 改版漏同步）
- **网盘不可信**：`size` 元数据不可信，以 md5 为准；刚签发的下载 URL 偶发失效
- **AI 推断须标注**：推断性结论标【AI推断·待确认】/【AI补充·待确认】，未经人工确认不算定稿
- **模板版本依赖**：当前绑定 QR-260D TD01 第1版，模板换版需重新定位 tc 索引
- **口径留意**：Skill 实际装在 **user-level** `~/.workbuddy/skills/`，日报曾记为「项目级」，对外表述统一为「WorkBuddy 技能（本机用户级）」
- **保密**：配方/客户信息不得进入任何对外内容，案例库文件带保密声明
