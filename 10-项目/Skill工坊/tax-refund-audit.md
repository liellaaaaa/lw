# tax-refund-audit（退税资料智能审核）

**日期**：2026-09-10 归档

> **一句话**：丢进来一批退税单据（文件夹/zip），AI 多模态直接「看」内容，跑完 P0 齐全性 → P1 字段抽取 → P2 九维跨文档对账，产出财务同事一眼能用的红黄绿灰 HTML 报告。

## 需求背景与两条技术路线

- **路线一（Tax_check 桌面项目，已停）**：RapidOCR + 文件名正则匹配的独立 FastAPI 应用，7-16~8-03 迭代 7 版后停更。致命伤：扫描件、印章遮挡、ZIP 乱码、跨文档对账全失效（靠文件名匹配天然不可靠）。
- **路线二（本 Skill，现行）**：AI 多模态读 PDF 文字层/截图，语义级一致性判断。**零依赖设计**——核心能力不依赖本地 Python，财务同事电脑没环境也能跑；脚本只是大批次时的可选加速（探测 PDF 类型/批量抽字/转存图片规避 Read 400 错误）。
- 项目档案：[[Tax_check]]（独立开发线，8/1 打包交付运营）；本 Skill 是其业务的能力升级形态。

## 业务口径（锁定，改前需业务确认）

- **P0 归类**：A 组 8 项必传；拖车费（看货代费用确认件内容）、监管仓库（看报关底单运输方式）、成交方式（CIF/FOB/C&F/EXW）三个条件触发，未激活条件单据标「不适用」不计缺失。
- **P1 抽字段**：以**报关底单为锚点**（最权威），抽 HS 编码/成交方式/商品名/数量/重量/总价/币制等作比对基准。
- **P2 九维对账**：HS 编码、商品名、数量、重量、总价（注意 CIF 含运保费口径）、成交方式、收汇差额、委托协议双核对+双方盖章、核注清单状态（预核扣/过卡）。
- **异常判定口径**：海运费/空运费免税 = 正常（早期误判过🔴）；港杂费/报关费开免税普票 = 🔴；收汇差额默认 🟡 非阻断（3% 是经验参考值非公司规范）；核注清单未过卡 = 🳡 保税通病。
- **ZIP 乱码不靠文件名**：GBK 解压乱码后一律内容识别，这也是旧系统的致命伤所在。
