# 开票明细工具 · 对账单追加

> **对接部门**：财务部
> **状态**：已完成并交付。
> **时间线**：2026-07 上旬（旧版 Skill）→ 2026-07-21（新版 HTML 工具）。

## 项目简介

为财务部做的对账单→开票明细转换工具。核心场景：

- 财务部每月从 ERP 导出**对账单-销售明细**（25 列 Excel），需要追加到维护中的**开票明细** Excel 表格
- 不是简单复制粘贴——涉及列映射、发票分组、日期格式化、序号续编、公式生成、已核销抵扣、规格文本转换等业务规则
- 经历了两个版本的迭代：**旧版 Skill（Python 脚本，AI 驱动）→ 新版 HTML 工具（纯程序，确定性执行）**

## 版本对比

| 维度 | 旧版（invoice-generator Skill） | 新版（对账单追加工具.html） |
|---|---|---|
| **运行方式** | WorkBuddy Skill，依赖 AI 模型解析文档 | 浏览器打开 HTML，纯程序执行 |
| **技术栈** | Python + openpyxl | HTML + JavaScript + SheetJS (CDN) |
| **核心逻辑** | AI 理解用户意图 → 调用 Python 脚本 | 用户直接选文件 → JS 读写 Excel |
| **稳定性** | ⚠️ 不稳定，依赖模型理解和文档解析能力 | ✅ 确定性，无 AI 依赖 |
| **功能** | 新建 + 追加，含公式/已核销抵扣/规格转换 | 仅追加（基于已有开票明细），更轻量 |
| **部署** | 需 Python + openpyxl 环境 | 零安装，双击即用 |
| **维护** | 三个脚本（generate.py / append.py / append_from_90.py），代码风格不统一 | 单一 HTML 文件，475 行 |

## 为什么做了两版

旧版 Skill 输出不稳定，核心问题：

1. **AI 模型理解能力有波动**：同一个对账单，不同时候执行结果可能不同
2. **文档解析是瓶颈**：依赖模型正确理解 Excel 结构、列映射关系
3. **输出不可预期**：财务数据要求精确，任何偏差都不可接受

结论：**Excel 精确数据处理场景，不适合走 AI Skill 路线，应该用确定性程序解决。**

## 新版技术方案

```
浏览器端（对账单追加工具.html）：
  选择对账单.xlsx + 开票明细.xlsx
      → SheetJS 读取两个工作簿
      → 按发票号码分组、列映射、日期格式化、序号续编
      → 追加到开票明细末尾，提供下载/覆盖保存
```

### 列映射（对账单 → 开票明细）

| 对账单列 | →   | 开票明细列 | 处理              |
| ---- | --- | ----- | --------------- |
| 发票号码 | →   | C     | 直接              |
| K码   | →   | D     | 直接              |
| 客户   | →   | E     | 直接              |
| 业务员  | →   | F     | 直接              |
| 总金额  | →   | J     | 直接              |
| 以前   | →   | K     | 直接              |
| 当月   | →   | L     | 直接              |
| 日期   | →   | M     | 格式化为 yyyy/mm/dd |
| 名称   | →   | N     | 直接              |
| 数量   | →   | O     | 直接              |
| 单价   | →   | P     | 直接              |
| 总额   | →   | Q     | 直接              |
| 规格   | →   | R     | 直接              |
| 汇总名称 | →   | S     | 直接              |
| 数量.1 | →   | T     | 直接              |
| 单价.1 | →   | U     | 直接              |
| 总额.1 | →   | V     | 直接              |
| 备注   | →   | W     | 写入"开票规格型号"列     |

### 关键逻辑

- **按发票号分组**：C 列长度 > 5 的视为新发票，同发票下的后续行归入一组
- **组间空 2 行**：每张发票之间插入空行分隔
- **序号续编**：自动扫描已有最大序号 +1
- **日期双格式**：A 列填当天日期（x月x日），M 列填 yyyy/mm/dd
- **保存方式**：优先用 File System Access API 覆盖原文件，降级时下载新文件

## 旧版 Skill 详情

> 源目录：`C:\Users\windows\Desktop\旧开票明细\invoice-generator\`

### 额外功能（新版未包含）

- **G 列公式**：`=VLOOKUP(E{r},[1]客户开票要求!B:C,2,0)` — 根据客户名查开票要求（依赖外部工作簿）
- **U 列公式**：`=S{r}*T{r}` — 汇总总额
- **V 列公式**：嵌套 SUBSTITUTE — 规格文本转换（kg→公斤、八成新桶→桶、-A1/-B1→删除）
- **已核销抵扣**：发票产品总额 > 发票总金额时，差额以负数写入 Q 列，E 列标记"已核销"
- **表头名与实际数据错位**：为保持与原手工文件一致，部分列表头名与实际存储含义错位

### 已知 Bug

- **append.py 列偏移**：规格公式写入了 W 列（应为 V 列），汇总名称写入了 X 列（应为 W 列）
- **generate.py 汇总公式硬编码行号上限 60044**
