## 一、可复用的一段话（需求池判断话术）

> **当业务部门提出"想持续盯某类数据 / 指标、定期看趋势和异动"时，若命中以下特征，即可复用采购分析助手已验证的技术栈快速搭建，不必另起炉灶：**
>
> ① 数据来自外部系统 / 网站，需定时抓取或对接 API；② 用户是决策层（采购 / 管理），每日查看趋势而非操作录入；③ 数据可公开或半公开（如原料行情）；④ 需要看板 / 图表展示 + 异动预警驱动决策；⑤ 反复查看监控而非反复生成文档；⑥ 业务已"监控化"但靠人肉盯盘 / 抄数。
>
> **典型长相**：每天 / 定期打开某网站或系统抄数做对比，靠人眼发现涨跌异常。
>
> **投入**：1 名全栈 + 1 名业务接口人，1 周跑通"抓取 → 入库 → 看板"最小链路 → 2 周预警 + 分析 → 持续迭代。

这段话可直接作为需求池「监控看板类需求识别标准」或向领导汇报的标准表述。

## 二、技术栈集合（采购分析验证过）

| 层 | 技术 | 角色 | 复用提示 |
| --- | --- | --- | --- |
| 后端 | Python + FastAPI + SQLAlchemy + Pydantic | 接口 / 业务 / ORM | 路由分层清晰，易扩展 |
| 数据 | Alembic（规范迁移）+ SQLite（可切 Postgres） | 存储 / 版本管理 | 用 Alembic 别手写迁移；高并发 / 大数据换 Postgres |
| 抓取 | httpx / requests（外部数据源） | 定时抓取 / API 对接 | **必做失败重试 + 幂等**，避免重复入库 |
| 可视化 | ECharts（折线 / 柱状 / 看板） | 趋势 / 排行 / 对比展示 | 按需引入，路由懒加载保性能 |
| 预警 | 规则引擎（价格异动 → alerts） | 异动提醒 | 规则与数据分离，便于业务调阈值 |
| 鉴权 | JWT（get_current_user） | 登录 / 权限 | 用户少够用 |
| 分析 | analytics 聚合 + 操作日志 + 用户行为追踪 | 决策支撑 | 漏斗 / 热力图 / 留存可选 |
| 前端 | 独立消费方（Vue / React 或纯页面） | 看板界面 | 纯后端可先不做前端，消费方另接 |

**一句话技术栈**：`FastAPI + SQLAlchemy + Alembic + httpx + ECharts`

## 四、何时不套这套（反向信号）

- 高并发（100+ 人同时操作）→ 推 SaaS 或独立后端架构
- 移动端 / 多端适配 → 推供应商或独立前端团队
- 多租户 / 复杂权限（角色 > 5 个）→ 推供应商系统（宏昊AI助手）
- 需反复生成文档 / 单证（非监控）→ 走 TT 协议文档生成型技术栈
