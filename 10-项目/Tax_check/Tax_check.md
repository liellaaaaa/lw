## 项目简介

为**外贸出口退税**场景做的资料审核工具。出口退税对资料完整性要求极高——退税资料缺失或名称不规范，会直接导致退税失败、税款无法退回。

本仓库当前实现 **P0 资料齐全性审核 + P1 OCR 内容识别**：
- 按文件名关键词 + **OCR 识别内容**判定**单据类型**（覆盖 16+ 种：PI、合同、提单、发票、装箱单、报关单、申报要素、境货/离境货物报关单、退税申报明细、外汇/收汇水单、保险、运费/海运费、内陆运、装港/起运港、booking、debit note、未退税证明、备注等）
- 依据**价格条款矩阵**（EXW/FOB/C&F/CIF）判断是否需要对应运费发票，校验「是否缺运费发票」
- **OCR 自动重命名**：识别后自动改名，仅处理未识别文件；支持双击改名重新匹配
- 校验拖车/运输条件、必传单据是否齐全
- **图片/PDF 预览**、底部配置栏（成交方式/运输方式/拖车费，支持自动推断）、**确认后导出按单据类型命名的 ZIP**

设计原则强调**数据不出境 / 本地运行**：通过 PyInstaller 打包为本地 .exe，文件不上传任何服务器。

## 技术栈

- **Python**：核心语言（OCR 分类、内容读取、规则引擎、后端接口）
- **FastAPI**：08-01 迁移至 FastAPI 架构（此前为纯静态 HTML+JS），后端接口独立化
- **RapidOCR**：OCR 识别，打包时自动定位模型
- **pdfplumber / pypdf**：PDF 内容解析（pdfplumber 优先，pypdf 兜底）
- **后端接口（main）**：确认/取消接口改为 body 传参，跳过重复校验；确认后自动跳转下一单据
- **HTML + CSS + JS**：主从式（master-detail）UI——左侧分组文件名/双击改名，右侧审核要点 + 文件预览，底部配置栏
- **PyInstaller**：打包 .exe（build.bat 自动定位 RapidOCR 模型）
- 完全本地运行，数据不出浏览器/服务器

## 系统架构

```
本地桌面应用（PyInstaller 打包，数据不出境）：
  tax_check_app/
    classifier    → OCR 识别后自动重命名（仅未识别文件）
    content_reader → pdfplumber 优先 / pypdf 兜底，读取单据内容
    rules         → 关键词→单据类型映射 + 价格条款矩阵（必传单据判定）
    main          → 后端接口（确认/取消 body 传参、跳过重复校验、zip 按单据类型导出）
    UI            → 主从布局：左分组文件名/双击改名，右审核要点+预览，底配置栏
                 → xls 乱码修复、zip 导出按单据类型命名
```
- 完全本地：文件不上传服务器，满足「数据不出境」合规要求
- OCR + 规则双通道：文件名关键词初判，OCR 内容补识别，覆盖命名不规范文件

## 数据模型

- 输入：`退税资料` 文件夹
- 单据类型（关键词 + OCR 识别，16+ 种）
- 价格条款矩阵：EXW / FOB / C&F / CIF → 决定是否需要运费发票
- 配置：成交方式 / 运输方式 / 拖车费（支持自动推断：保税核注清单→监管仓库，国内运输单→拖车费存在）

## 核心功能模块

- **tax_check_app/**：应用主目录
- **classifier**：OCR 自动重命名
- **content_reader**：PDF 内容解析
- **rules**：关键词与价格条款矩阵规则
- **main**：后端接口（确认/取消、zip 导出）
- **UI（主从布局）**：分组文件名 / 双击改名 / 审核要点 / 预览 / 配置栏
- **build.bat**：自动定位 RapidOCR 模型并 PyInstaller 打包

## 亮点 / 可复盘点

- **OCR 自动重命名**：命名不规范的文件也能识别归类，补齐了 P0 仅靠文件名时的盲区
- **数据不出境**：本地 .exe，适合合规敏感的外贸企业
- **主从式审核界面**：左看实际文件、右看审核要点与预览，财务核对体验直观
- 用「文件名关键词 + 价格条款矩阵 + OCR」做资料齐全性体检，思路可复用于其它单证审核
- PRD 完整，是「需求 → 原型 → 迭代」的好样本

## P2 LLM 智能审核（skill 化落地）

- 2026-08-12 将退税审单封装为 WorkBuddy user-level skill（tax-refund-audit），以 AI 多模态替代原 OCR + 关键词方案，补齐跨文档语义级一致性比对能力（旧方案在扫描件、印章遮挡、ZIP 乱码、跨文档对账上会失效）
- 三级审核：P0 单据齐全性归类 → P1 字段抽取（以报关底单为锚点）→ P2 跨文档 9 维度一致性比对（HS 编码 / 商品名 / 数量 / 重量 / 金额 / 成交方式 / 收汇 / 委托协议 / 核注清单），输出红黄绿灰财务友好 HTML 报告
- 08-12 实战：WA231 HT260225SZ（USD8227.5，C&F 成交 / 监管仓库运输），结论 0 异常 / 2 需关注（收汇差额 $220 约 2.67% LC 银行费用、出口核注清单预核扣未过卡），必传 8/8 齐备，整体通过
- 规则权威源：退税资料审核 PRD 规则清单（prd_checklist）；收汇差额 3% 为我方经验参考值、非公司硬性红线，货代发票海运费免税属正常

## 需注意的已知问题

- OCR 对模糊/低质量扫描件识别率受限，需人工复核重命名结果
- 关键词匹配仍对文件名规范有依赖（OCR 已补齐大部分）
- 大文件夹（上千文件）下遍历与 OCR 性能需实测
