## 宏昊AI助手 系统架构与组织（2026-08-17 梳理）
- **内容链路（核心架构）**：文档管理中心 → 批量生成知识库 → 智能体关联多个知识库。文档管理中心的文档可批量选中生成知识库，一个智能体可关联多个知识库。AI小组正推动**文档管理中心作为唯一内容入口**，以后逐步关停公共盘 / ima知识库 / 个人电脑等零散来源。
- **内编 / 外编**：内编 = 产品身份证（如 NB001，研发上传说明书解析到文档管理中心得到）；外编 = 业务员拿到的产品编码（如 HT-001，开稀配低浓度后命名 HT-001A）。内编仅文档管理中有权限人员可见；说明书助手等关联知识库后**不显示内编**——这是"内编关联查找说明书"诉求的根源（业务员需用内编精准定位，但权限受限）。
- **能力边界**：支持图片(OCR识别)/PDF/Word/Excel **上传**；**不支持输出文件**（聊天框只能给文本，无法生成可下载的 Word/PDF）。另有专门的**翻译对话机器人**，能中英翻译但不能输出文件。
- **资料散落根因**：研发做实验后不一定全量上传说明书，理化指标等实验数据散落各处、前后不汇合——这是智能体回答"理化特征缺失 / 不准确"的根因之一，需推动研发规范上传流程。
- **组织角色（职责边界）**：研发 = 说明书 / 内编外编 / 实验数据上传的源头；AI小组(肖聪) = 推文档管理中心统一、内容运营监督与排查（非代传资料）；领导 = 拍板内编脱敏/权限方案。跨部门推动时动作分给真实执行方，肖聪只负责推动与对接。

## 宏昊AI助手 项目认知与阶段判断（2026-08-17 形成）
- **阶段定位**：已过"从0建设"，进入"内容治理/统一收口"阶段（文档管理中心收口零散来源即信号）。当前主要矛盾是内容质量与拉齐，非功能有无。
- **质量瓶颈在上游数据治理，不在模型**：回答不准/理化缺失的根因是研发实验数据不全量上传、资料散落。提示词优化(⑦)是止血治标，研发流程规范才是治本；技术修补见效快但治标，组织推动难但治本——排优先级时据此区分"快赢"与"根治"。
- **核心 persona = 外贸业务员**：外贸部最重最苛（英文TDS/海关/多语种/客户背调），价值最强；销售部门多用说明书/话术/工艺。功能建设应优先向外贸痛点倾斜。
- **内编权限矛盾 = 信息安全 vs 一线可用的跨层级张力**：解法需领导拍板，AI小组只出方案不定策。
- **采纳度是隐形风险**：71%满意但存在低频/未使用人群，且"填未使用实际用过"→工具未嵌进日常流，有"用了但没习惯/没意识价值"的 gap，需运营推动固化。
- **AI小组是"推动+对接"中枢，进度被他人配合度卡住**（研发上传、领导拍板、运维开发）。项目风险不在技术，在跨职能协同。
