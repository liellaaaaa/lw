## 一、写入与格式红线（最高优先级）
- **🔴 读不了图片就说读不了，绝不推测填补**（2026-09-01 教训：我曾编造金额/家数/书目，差点进公司纪要）。只能做「骨架版」：只采信用户文字，数字/人名/书名一律留 `【待补：截图 N】`，文件头标明骨架版。
- **🔴 学习内容不直接入库**（2026-08-07）：用户分享的文章/公众号/外部资料属"输入型内容"，不直接整理落库。先反问引导用户自己输出观点，完成内化后再决定。格式因时制宜，不套固定模板。
  - **2026-09-04 验证有效的流程**：①我提炼原文干货 + 给出自己的判断（可以有观点、可以驳用户）②抛 2–3 个具体问题引导他结合自身项目回答 ③他回答后再落库。落库时**不要只存摘录**——把抽象出的可复用规则**并入已有正式知识笔记**（那次把"穷举幻觉"等规则并进 `20-知识/AI工具与Skill制作/AI集成策略-三种模式与选择.md`，顺带修正了其中已被推翻的旧结论）。
- **决策日志机制**（2026-09-04 用户提出并建立）：文件 `20-知识/决策日志.md`。用户做决策前先说，由我补问并落记录：三要素＝①背景+备选方案 ②为什么选这个 ③**可验证的预期**（必须可量化，不写"应该会好一些"）；落地 2~4 周后回来对答案。结构＝顶部索引表（D00X 递增）+ 分条展开。**核心：过去的文件只记"发生了什么"，必须补上"当时预计会发生什么"，否则无从校准。**
- **写深别写壳**（2026-08-17）：笔记要沉淀可复用提示词、流程框架、关键数据、方法论、避坑清单，不能只写"谁讲了啥"。**结构顺序：标题下第一行写 `**日期**：…`，再展开正文**。
- **项目日志写法**（2026-08-06）：每条一两行，只写做了什么/改了什么，**不写函数名、文件名、代码方法、实现细节**。
- **验收与问题反馈分库 + 按月分文件**（2026-08-25 / 09-04）：验收结果只进验收汇总；问题反馈只进反馈汇总，两者不混。**当月反馈只进当月文件，绝不跨月追加**；新月份先建文件（沿用标题+引用块+`### 反馈记录` 表格，列：时间/来源/板块/详细内容/结论）。
- **周会纪要**：纯文本不要表格（汇报正文）；主持人 ≠ 点评人，点评归点评人名下；截图常有人名错挂需按用户提示修正并在末尾说明；存放 `20-知识/会议整理/YYYY-MM-DD_总经办周会.md`，写完更新同目录 `README.md` 索引。汇报顺序：肖聪-刘妍妍-邱乐-穆杨-张海容-邓楚羿-李文婷-韦妹琴-方伟洪。
- **日报**（08-03 授权）：AI 可在用户简写基础上补全展开，直接落 `01-每日记录/日报/YYYY-MM-DD.md`，无需逐条确认，写完更新 `日报索引.md`。缩写：TT助手=shippiing_helper；业务陪练=ai-sales-coach；退税审单=Tax_check；采购分析=ProcurementAnalysis；文婷姐=审核对接人。
- **月报**：`01-每日记录/月报/YYYY-MM-月报.md`，从日报周报汇总，写完更新索引。

## 三、项目日志与 GitHub 同步（2026-09-04 形成）
补日志**先拉提交历史再落笔**，不要凭印象。仓库地址在各项目主文件 frontmatter 的 `repo` 字段，`since=[日志最后日期]` 拉取。写完同步三处：①主文件「开发历程」表格 ②frontmatter `updated`/`github_pushed` ③问题反馈文件里对得上的条目闭环（标"已调整+提交日期"）。
- 本地仓库位置：优先读主文件 `local_path`；否则去 `C:\Users\windows\Desktop\<项目名>`。
- **坑**：Git Bash 的 `/c/Users/...` 对桌面项目报 No such file or directory，改用 **PowerShell** 跑 git；Read/Edit/Write 用反斜杠路径正常。
- 涉及代码仓库的改动，**用户没明确说推送就只改本地，不 commit/push**。

## 四、宏昊AI助手 / 公共知识库
- **架构**：文档管理中心 → 批量生成知识库（向量化+切片）→ 智能体关联多知识库。文档管理中心＝公司唯一文件入口（内部称"企业公共知识库"），正收口公共盘/ima/个人电脑等零散来源。
- **内编/外编**：内编＝产品身份证（NB001），仅文档管理有权限者可见，关联知识库后不显示；外编＝业务员拿到的编码（HT-001）。业务员需用内编精准定位但权限受限 → 这是"内编查找说明书"诉求根源，解法需领导拍板。
- **能力边界**：支持图片(OCR)/PDF/Word/Excel 上传；**不支持输出文件**。
- **迁移总纲**：只迁公司大公共盘；三角责任＝部门助理(执行)/部门负责人(确认)/验收负责人(检查)；8/26 启动，9/9 验收关库；验收五项＝范围完整·清理完成·目录正确·信息完整·权限版本正确；月度维护＝每月 15 日前完成+随后 2 个工作日检查。
- **硬约束**：单次上传 ≤300 文件；必须选末级业务目录；**文档类别+标签必填**；L1 目录仅最高权限管理员可建（向肖聪申请），L2+ 部门自建需填名称+编码；同名新覆盖旧，旧件成历史版本可回滚；权限可到个人/角色，有下载开关。
- **已知缺口**：类别与标签使用次数全为 0（本轮首次启用）；类别中培训类占近半，人事表单/报关单证/客户案例/会议纪要/质量标准落不下；目录命名全半角混乱；各部门存量悬殊（研发 2608 / 制造 1124 / 质量 1082 vs 外贸 2、客服 3）。
