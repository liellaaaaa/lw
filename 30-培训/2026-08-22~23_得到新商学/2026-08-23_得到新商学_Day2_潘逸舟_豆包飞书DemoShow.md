# 潘逸舟（豆包 + 飞书）· 豆包 + 飞书 1+1>2：三类场景把活真正干出来

**日期**：2026-08-23（周日）
**培训人**：潘逸舟（豆包企业版 / 飞书协同实战派，长期陪跑企业落地 AI 场景）

**来源**：Day2 现场逐字转写整理（lw 在场实录）
**适用读者**：负责把 AI 落到企业流程 / 内容生产 / 数据分析的负责人
**配套**：跨嘉宾横向 → [[2026-08-23_得到新商学_Day2硬件出海与AI增长大会]]

## 一、一句话核心方法论

**「光靠豆包，效果可能是一次性的；豆包企业版 + 飞书一起用，才叠加出组织协同——豆包负责'执行与生成'，飞书负责'承载、权限、可协作'，把一次性 AI 操作变成稳定可追踪的业务流程。落地先分三类场景：干掉重复的活 / 干好花钱的活 / 干轻数据的活」**。

三件事的排列：① 三类场景 → ② 豆包 + 飞书 1+1>2 的分工 → ③ 两个通用技巧（skill 拿来改 + 四框架沟通）。以下逐条展开。

## 二、三类场景：企业里 AI 到底能干什么

潘逸舟把企业 AI 落地归纳为三种活：

| 场景 | 含义 | 例子 |
|---|---|---|
| 1. 干掉重复的活 | 搬运数据、汇总材料等机械性事务 | 视频网拍每天重复汇总 + 视频制作；舆情分析看板 |
| 2. 干好花钱的活 | 原本要外包 / 雇人 / 买厚系统的活 | 搭轻应用系统（合作商管理）；生图符合企业规范；带货短视频批量生成 |
| 3. 干轻数据的活 | 数据清理与分析 | 调研材料分析；直播数据分析；投放效果日报归因 |

> 潘逸舟的原话基调："我们今年最大的体感，原本用的 AI 是'跟你聊天的 AI'，现在它是'能直接给你交付成果的 AI'。"

## 三、场景一拆解：干掉重复的活（爆款仿拍 + 舆情看板）

**爆款仿拍流水线**（结合豆包 + 飞书多维表格）：
1. 指令："打开抖音，搜索 AI agent 相关 top10 爆款，采集标题 / 点赞 / 评论 / 内容类型 / 账号，整理到飞书多维表格，归纳爆款共性规律"
2. AI 读取视频内容，总结爆款原因（如"达人背书 + 标题击中焦虑"）
3. 打标：采纳做仿拍 / 忽略；设**定时任务**每天 10-12 点自动识别状态、结合爆款总结批量生成视频
4. 价格参考：约 1 元 / 秒，且豆包 + 多维表格能"持续产出"而非一次性

**舆情 / 客户之声分析看板**：
- 多平台用户反馈，以前要登录不同平台截图汇总，现在用 skill 按标准流程分析
- 生成**实时计算**的看板，可直接链接原帖，后续动作更直观

> 关键：生成本地文件复用性差；生成到飞书里的 **HTML 网页版且可编辑**材料，兼顾美观、互动、可编辑，还能带权限分享协作——不是一次性材料。

## 四、场景二拆解：干好花钱的活（轻应用 + 设计规范 + 视频）

**轻应用系统搭建**（长尾需求）：
- 例子：境外旅游客户需每天选合适协议酒店，买 SaaS 不值得，用豆包 + Agent 快速搭
- 步骤：把 Excel 表导入多维表格 → AI 理解表间关系 → 自然语言说"改一下组合"就能调系统（以前找供应商改要排期评估）
- 核心价值：改需求变得容易，企业内部可复用

**符合企业设计规范的材料生成**：
- 指令："我要着 AR Build 开放日，结合企业设计规范标准，帮我设计一套完整素材"
- AI 先读内部所有规范核心要求（以前交互很麻烦，现在飞书 / 存储平台直接给）→ 产出系列图 → 顺带改尺寸、调元素

**做视频的四个步骤**（潘逸舟总结）：
1. **写好分镜脚本**（十几秒视频，每步呈现什么）
2. **确定关键环节呈现形式**，关键是图片，先审核
3. **生成视频**
4. **拼接**

> 原则："没有一个好视频是一句话直出的。"先读公司产品等信息再产出。品味决定上限——参考来自技能 / 网站 / 企业积累数据。

**带货短视频批量生成**：用"带货 Skill"，丢一张产品图，快速生成 15 秒带货小视频（跨境朋友直接用）。适合做特效镜头、KOL 推广等实拍不易完成的活。

## 五、场景三拆解：干轻数据的活（数据归因 + 交叉校准）

**投放效果日报归因**：
- 设任务：每天抓取相关主题群聊和会议，汇总前因后果到多维表格
- 设定时任务：每天把重要事情、前因后果、丰富沟通信息汇总成日报
- 比单独找下属沟通信息量大得多

**数据分析的两个经验**：
1. **要求讲清楚**：取什么时间段、取哪些数、输出什么结构——写不清输出就偏
2. **交叉校准（最重要）**：一个任务框产出数据 → 丢给另一个任务框再跑一遍 → 抓取做交叉对比校准，报告准确率大幅提升

> 豆包做"理解数据、分析数据"，飞书做"业务数据存储、权限管控、数据沉淀"——结合后才能把散乱文件快速分析成可决策、可持续使用的业务成果。

## 六、豆包 + 飞书 1+1>2 的分工模型

潘逸舟反复强调："光靠豆包，效果可能是一次性的。豆包企业版 + 飞书一起用，叠加出组织协同。"

| 场景 | 豆包负责 | 飞书负责 |
|---|---|---|
| 干掉重复的活 | 执行（调用技能、跑流程）| 让任务变成持续运转的托管式流程（多维表格承载状态、群聊推送）|
| 干好花钱的活 | 生产内容和应用 | 企业内部数据 + 专属技能的量级承载，提供基座 |
| 干轻数据的活 | 理解、呈现数据 | 结构可编辑、可分享、可协作 |

> 三种使用形态：① 独立复杂任务 → 在豆包页选模型执行；② 专业任务结合内部系统 → 用企业自创 / 通用 Skill；③ 每天固定重复 / 每周循环 → 定时任务。

## 七、两个通用技巧

**技巧 1：skill 不是拿来用，是拿来改的**
- 豆包企业版精选了大量企业案例、预装实用技能（如华硕 PPT 美化 skill、HTML 材料 skill）
- 建议：先用 skill 学**框架思路**，再结合企业实际**修改**成自己的资产
- "别把鸡蛋放在同一个 AI 任务里"：常线程任务用豆包；短线程批量任务（每日爆款仿拍）用数据库存储 + 自动化执行

**技巧 2：与 AI 沟通用"四框架"**
把 AI 当"聪明但不熟悉你企业的实习生"，一句话包含四要素：

| 要素 | 含义 | 例子 |
|---|---|---|
| 对象 | 数据来源 | 从产品反馈群取数据 |
| 范围 | 时间 / 边界 | 最近 7 天 |
| 动作 | 要做什么 | 汇总成表格 |
| 交付物 | 输出到哪 | 写回飞书文档 |

> 四要素齐了，AI 产出效果就好。

**审美提升锦囊**：
- 用专门网站抓取全球审美优秀的公司官网，下载 HTML / 提示词，1:1 像素级复刻设计元素
- 关注优秀博主（如飞书同学 Zara）的 HTML 审美技能分享
- 开局先让 AI 开头，结构化后再用参考 / 设计工具提升——避免每次"抽卡"

## 八、从 PPT 转向 HTML 材料（强烈建议）

潘逸舟与马想都强调："今年非常建议从 PPT 材料转为 HTML 材料。"

HTML 材料的三个优势：
1. **AI 可读**：希望 AI 大量进入企业做分析，材料要让 AI 易读
2. **人看着舒服**：交互式、可实时调参（如选"稳健版 / 保守版"，预算分配、收支利润预测实时变）
3. **可编辑可协作**：飞书里点击分享带权限，同事可二次编辑、评论、持续推进，不是一次性材料

> 潘逸舟自己的分享材料就是 HTML 做的，可切入大量数据和系统界面，给客户呈现更直观。

## 九、可复用提示词 / 话术

1. **"光靠豆包，效果可能是一次性的；豆包 + 飞书才叠加出组织协同"** —— 落地架构总纲
2. **"没有一个好视频是一句话直出的"** —— 视频 / 任何产出都要分步
3. **"skill 不是拿来用，是拿来改的"** —— 复用而非照抄
4. **"四框架：对象 / 范围 / 动作 / 交付物"** —— 给 AI 发任务的最小完备句式
5. **"数据交叉校准：一个框产出，丢给另一个框再跑一遍"** —— 提升分析准确率
6. **"从 PPT 材料转为 HTML 材料"** —— 今年材料形态建议

## 十、避坑清单（潘逸舟版）

| # | 坑 | 真实后果 |
|---|---|---|
| 1 | 只用豆包不做流程承载 | 一次性产出，无法追踪复用 |
| 2 | 生成本地文件不进协同系统 | 复用性差，同事用不了 |
| 3 | 做视频想一句话直出 | 效果差、不合规 |
| 4 | 数据分析要求写不清 | 输出偏差大 |
| 5 | 单任务框出数据不校准 | 偏差无人发现 |
| 6 | 照抄别人 skill 不改 | 不合企业实际，用两次就弃 |
| 7 | 买厚重 SaaS 改需求排期 | 用起来极不顺手 |
| 8 | 材料只用 PPT | AI 难读、协作弱、一次性 |

## 十一、lw 联想（外贸 / 采购 / AI 项目方法论）

### A. 与外贸业务线相关的 3 件可做之事

1. **外贸"爆款仿拍"式内容流水线**：把潘逸舟的多维表格 + 定时任务思路用于外贸社媒——每天抓取行业 top 内容、拆解共性、批量生成开发信 / 朋友圈素材，沉淀到 shippiing_helper 或外贸助手。
2. **客户之声舆情看板**：把各平台（阿里国际站 / 社媒）客户反馈用 skill 汇总成实时看板，对应 Day1 李文录"关心客户生意"——让业务真看到客户痛点。
3. **四框架写外贸 prompt**：把"对象 / 范围 / 动作 / 交付物"作为外贸 skill 的标准句式，避免现在 prompt 模糊导致输出跑偏。

### B. 与采购分析业务线相关的 2 件可做之事

1. **采购数据交叉校准**：ProcurementAnalysis 出的报表，用潘逸舟"两个任务框互校"法——一框出数，二框复核，提升准确率，减少人工怀疑。
2. **供应商反馈 HTML 看板**：把采购分析报表从静态 Excel / PPT 转成飞书里的 HTML 可交互看板，领导可实时调参（如"如果铜价涨 10%"），辅助决策。

### C. 与 AI 项目方法论相关的 3 件可做之事

1. **宏昊AI助手输出转 HTML**：目前宏昊AI助手 / 培训助手输出偏文本。应学潘逸舟"HTML 材料"——输出可编辑、可交互、AI 可读的网页，便于在企微 / 飞书流转协作。
2. **skill 拿来改机制**：公司内部已有退税审单、采购分析等 skill，应建"skill 市场 / 模板库"，新人先学框架再改，避免每人从零造（对应张老师"skill 是员工手册"）。
3. **豆包 + 飞书 / 企微 协同架构**：宏昊若引入豆包企业版类能力，必须配"飞书 / 企微做承载 + 权限 + 协作"，否则又是一次性噱头——这是潘逸舟全程最核心的提醒。
