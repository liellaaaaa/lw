## 一、WorkBuddy 核心定位——"给大模型装手脚"

### 三类 AI 产品边界（必须分清）

| 类型 | 能力 | 类比 | 落地局限 |
|------|------|------|----------|
| 普通对话AI（豆包等） | 纯文本对话 | 只有一张嘴 | 不能读本地文件、不能输出交付物 |
| 大模型底座 | 语言处理+信息读取+生成推理 | 大脑 | 通用能力，不接入具体工作流 |
| **WorkBuddy 智能体** | 对话 + 文件读写 + 调用专家/Skill + 连接第三方应用 + 自动化执行 | **大脑 + 手脚** | 将AI能力转化为可落地、可复用的办公成果 |

**核心价值判断标准**：如果一个工具只能对话不能产出文件/执行动作，它就停留在"聊天玩具"阶段。WorkBuddy 的差异化在于**闭环执行**——从输入材料到产出交付物，全程不需要人工切换应用。

## 二、基础交互与关键配置

### 三种运行模式

| 模式 | 行为 | 适用场景 | 建议 |
|------|------|----------|------|
| **Plan模式** ✅推荐默认开启 | 多轮提问确认意图，理解完整后再执行 | 复杂任务、新用户、重要产出 | **日常使用务必开启** |
| 仅问答模式 | 不读文件、不执行操作，纯对话 | 只想问问题不想动文件时 | 临时切换 |
| 默认模式 | 收到指令直接执行，无确认环节 | 简单明确的一次性指令 | 熟练后可用 |

> ⚠️ **踩坑记录**：Plan模式不是限制，是保护。关闭Plan模式后AI会按自己的理解直接执行，经常产出不符合预期的结果（比如格式不对、遗漏要求）。新手期建议始终开启。

### 工作空间（Workspace）

- **本质**：给AI划定专属"工位"，一次任务中所有读取的文件和生成的交付物都集中存放在该目录
- **不配置的后果**：文件散落在C盘各处，后续找不到、管理混乱
- **正确做法**：
  1. 设置 → 修改全局默认输出路径到非系统盘（如D盘）
  2. 每次启动重要任务前，先选定对应的工作空间文件夹
  3. 不同项目用不同文件夹隔离

### 积分规则

- 新人注册赠送 2000 积分
- 模型版本数字越大 → 能力越强 → 积分消耗越快
- 专家团队模式因调用多角色，积分消耗速度显著加快
- 持续使用需充值

## 三、三大核心能力：专家 / Skill / 连接器

### 专家功能

- **定义**：封装了特定领域的专业方法论、知识库与标准执行SOP的"虚拟专业员工"
- **用法**：搜索领域关键词（如"数据分析"）→ 召唤专家 → 它会自带提示词框架和领域知识
- **专家团队模式**：多角色分工处理复杂分析任务，能力强但积分消耗快
- **适用**：需要专业方法论支撑的任务（安全库存测算、行业分析报告等）

### Skill（技能）——最核心的复用能力

**定义**：将"固定流程的重复任务"封装为可复用的"压缩包"，一次制作、多次调用。

**制作流程（以周报为例）**：
```
第1步：给AI输入本周完成事项
第2步：提供周报模板
第3步：让AI读取历史周报（学习口吻和风格）
第4步：告知领导偏好（如"不要啰嗦，只说重点"）
第5步：AI生成周报 → 反复修改直到满意
第6步：发送指令「把这个过程保存为Skill」→ 安装完成
第7步：以后直接调用该Skill，只需输入本周事项即可
```

**Skill vs 轻量应用的选型判断**：

| 维度 | Skill | 轻量网页应用 |
|------|-------|-------------|
| 输入 | 每次变化（如每周不同工作内容） | 相对固定或需交互界面 |
| 执行逻辑 | 完全固定不变 | 固定 |
| 交互需求 | 无需界面，命令行触发 | 需要可视化界面、按钮操作 |
| 典型场景 | 周报生成、日报汇总、简历筛选 | 成本计算器、双表追加工具 |
| 开发成本 | 低（自然语言描述即可） | 中等 |

**Skill迭代优化的关键方法**：
- 初版不满意？**不用改代码，直接用自然语言提需求**
- 例："现在全是文字看着累，帮我改成HTML可视化展示，加上亮点/风险点/面试追问建议"
- AI会自动升级Skill到2.0版本，重新验证效果

### 连接器功能

已支持的第三方应用及典型操作：

| 应用 | 可执行操作 | 场景示例 |
|------|-----------|---------|
| QQ邮箱 | 读取邮件、回复邮件、发送邮件 | "回复我的第一封未读邮件" |
| 腾讯会议 | 创建会议、读取会议记录 | "创建今天下午6点的会议，时长1小时" |
| 百度网盘 | 读取/上传/删除/更新文件 | 远程管理网盘文件 |
| 企业微信 | 推送消息、机器人交互 | 自动化结果推送 |

> 💡 **效率提升点**：连接器最大的价值是减少跨平台切换。原本需要打开3个App完成的操作，现在一个对话框搞定。

## 四、自动化任务

### 配置要素

```
自动化名称 → 关联工作空间 → 提示词（要做什么）→ 触发时间 → 推送目标（企微机器人/微信小程序）
```

### 典型案例：采购每日原料行情早报

1. 采购部在指定网站放置原料行情链接
2. 建立自动化任务：每日8:30执行
3. AI自动爬取网站数据 → 生成行情分析卡片
4. 推送到企业微信机器人
5. **完全替代人工每天手动打开网站抄价格**

### 时效性控制的关键技巧

对于时效性要求高的场景（如每日早报），必须在提示词中显式限定时间范围：
- ❌ "给我一份纺织化工行业简报"
- ✅ "我只需要最近24小时内的信息，今天是8月21日，18号及之前的旧信息一律不要，只保留20号、21号的内容"

### 助理机器人配置

- 在"助理"中配置企业微信/微信连接
- 连接后生成专属机器人
- 通过企微/微信直接发指令触发任务执行
- 例：在企微里说"读取我的腾讯会议记录"即可获得会议内容摘要

## 五、AI适配工作场景的5步判断法（核心方法论）

这是本次培训最重要的方法论框架，适用于任何岗位识别AI落地场景。

```
第1步 定位候选任务
    ↓ 从近一周真实工作中筛选：重复度高、耗时长、信息量大的细分环节
    ↓ ⚠️ 不要试图替代整个岗位，只替代其中一个小环节
    ↓ 例：不是"用AI替代销售"，而是"用AI整理客户拜访记录生成跟进清单"
    ↓
第2步 验证5个适配条件（缺一不可）
    ├── ① 有AI可识别的输入材料（手绘图纸❌ Excel/Word/PDF✅）
    ├── ② 执行过程可清晰描述（有明确的步骤逻辑）
    ├── ③ 有明确的标准化产出物（不是"帮我想想"而是"算出成本价"）
    ├── ④ AI效率显著高于人工（值得做）
    └── ⑤ 产出结果可人工复核校验（有兜底机制）
    ↓
第3步 拆分执行环节
    ↓ 标准流程：收集信息 → 整理信息 → AI分析 → 人工校验 → 对外执行
    ↓
第4步 明确人机边界（⚠️ 最关键的一步）
    ├── ✅ AI负责：整理文件、提取信息、生成初稿、提示遗漏点、批量计算
    └── ❌ 人工负责：敏感信息脱敏、关键业务判断、最终审批、对外通知
    ↓
第5步 验收与推广
    ↓ 用预留的真实数据验证准确性 → 测算节省时间比例 → 确认可稳定复现 → 推广团队使用
```

### 人机边界的铁律

> **敏感信息与关键决策绝对不能交由AI自主完成。** 这不是技术限制，是风险控制底线。

## 八、实操演示详解

### 实操1：人事人才筛选Skill开发

**需求描述模板（可直接复用）**：

```
我是[岗位]，我要制作一个Skill，用途是快速筛选符合需求的候选人。
筛选依据：公司有岗位职责表和胜任度标准表。
评判标准：[列出硬门槛和软性要求]。
输出要求：多维度评分 + 是否推荐面试 + 面试追问建议。
```

**迭代优化路径**：
- V1.0：纯文字评分 → 可读性差，信息密度低
- V2.0（自然语言升级）：HTML可视化八维评分表 + 权重证据 + 亮点/风险点 + 面试追问建议
- **关键经验**：不用改代码，直接告诉AI你想要什么形式的输出，它会自动重构Skill

### 实操2：采购每日早报 + 自动化推送

**增强提示词的使用方法**：
1. 先用大白话写一行基础需求（"我是XX厂的，帮我出一份纺织化工行业简报"）
2. 点击"增强提示词"按钮，AI自动补全结构化细节（信息来源、内容维度、时效性、输出格式）
3. 人工审核补全后的提示词，微调不符合预期的部分
4. 确认后执行

**自动化配置要点**：
- 提示词中必须包含时效性约束（"只取最近24小时"）
- 推送目标选企微机器人
- 建议设置在上班前自动推送（如8:30），到岗即可查看

### 实操3：原料价格深度数据分析

**向AI描述数据的正确方式**（关键！）：

```
❌ 错误做法：扔过去一份数据说"帮我分析"
✅ 正确做法：
  - 数据源是什么（原料价格表，跨度X个月）
  - 每列字段的含义（第1列=原料名，第2列=出厂价，第3列=市场价...）
  - 字段间的计算关系（第1列×第2列=总价）
  - 你希望怎么分析（价格走势、波动预警、相关性、成本优化建议）
```

**输出报告包含的模块**（参考）：
- 成本指数走势图
- 价格预测
- 相关性热力图（哪些原料价格联动）
- 溢价空间分析
- 预警信号（暴涨/暴跌原料）
- 成本结构拆解
- 行动矩阵（建议采买/观望/锁价的品种）

### 实操4：研发配方成本计算工具（现场共创）

**现场需求梳理过程**（体现如何引导业务人员提需求）：

```
讲师：你要做一个什么工具？
学员：计算配方成本的。
讲师：你需要输入什么？
学员：原料名称、配方比例、原料价格、收率。
讲师：计算公式是什么？
学员：通用的。（原料总成本 = Σ(单价×比例)，配方成本价 = 总成本÷收率）
讲师：输出什么？
学员：成本价，以及各原料的成本明细。
```

**从粗糙需求到完整提示词的过程**：
1. 学员用大白话说了基本需求 → Ctrl+A 复制
2. 使用"增强提示词"功能自动补全细节
3. AI补全后逐项确认：表格录入方式、独立参数（收率）、计算公式、输出排版、数据校验
4. 确认无误后让AI开始生成轻量网页工具

> **大白话原则**：跟AI提需求不用讲技术术语，把输入、过程、输出讲得越清楚，结果越符合预期。

## 九、企业微信智能助理（大圆）实用场景

### 已验证的场景

| 场景          | 操作方式                               | 效果                          |
| ----------- | ---------------------------------- | --------------------------- |
| **日报自动总结**  | 每天让大圆自动总结当日工作                      | 沉淀细粒度工作记录                   |
| **周报从日报汇总** | 让大圆从历史日报中汇总生成周报                    | 比直接写周报完整得多（不会遗漏80%的细节）      |
| **待办清单**    | 每天17:30汇总未回复消息+未完成任务，按优先级排序推送到待办模块 | 第二天开工即有清晰的行动清单              |
| **读书笔记汇总**  | 从文件传输助手汇总读书笔记 → 生成全书脉络概要           | 快速回顾整本书框架                   |
| **个人工作复盘**  | 投入历史工作数据（如入职以来的全部日报）→ 量化复盘报告       | 内部/外部工作分类、亮点项目、时间线、量化指标一目了然 |

### 日报→周报的数据链路（关键洞察）

```
直接写周报 → 遗漏严重（7件事可能只想起2件）
     ↓
改为：每天写日报（AI自动总结）→ 周末从日报汇总周报
     ↓
结果：周报内容完整、有条理、有脉络
```

**原理**：AI的记忆窗口有限，不可能一次性回忆起一周的所有工作。但如果你每天都沉淀了日报，它就能从已有的日报文本中精准汇总，不再依赖"回忆"。

## 十二、关键金句与原则

1. **"不要试图用AI替代整个岗位，我们只需要用AI替代岗位里某一个重复耗时的小环节就够了。"**
2. **"跟AI提需求不用讲高深的技术术语，用大白话把输入、过程、输出讲得越清楚，它的结果就越符合你的预期。"**
3. **"AI落地优先选最轻最稳的交付形态，一上来就做复杂应用反而容易失败。"**
4. **日常使用必须优先开启Plan模式，执行重要任务前必须先选定工作空间。**
5. **敏感信息与关键决策绝对不能交由AI自主完成——这是铁律，不是建议。**
