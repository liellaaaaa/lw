# 8.3-8.8 · 周报

## 本周关键成果

### 一、TT 协议自动化工具（shipping_helper / 船务助手）

围绕报关资料生成与包装计算做了多轮修复，并响应船务部一线反馈收敛规格：

- **报关资料显示修复**：① 币制显示中文化（USD→美元、CNY/RMB→人民币），不再用英文缩写；② 报关单按产品数动态扩展行数，解除原 6 个产品上限，模板可承载更多产品项；③ 修复毛重、CBM 等计算字段的生成逻辑。
- **卡板装载规格统一**：与潘慧兰沟通确认，1 米与 1.1 米卡板装载 60kg 蓝桶的最大数量统一为 **18 桶/卡板**；据此在后台补入 1.1 米外贸专用消毒卡板的包装预设，修复此前卡板数量未自动算出的问题（此前数据库仅缺该预设）。
- **PI 解析修复**：处理李雪反馈的 PI 合同表数据未解析问题——根因为粘贴行首片段未合并导致整行未识别；同步排查了重复汇入数据导致的错误，已修复。
- **配套增强**：PI 目的港解析统一归一化、国家/港口映射集中管理；入库前增加包装计算校验（可强制入库未计算包装的产品）；同一产品支持拆多行录入、各带独立包装数据；目的港台账保留源数据；MSDS 台账导入增加必填校验。
- **关联修复**：8/3 修复采购分析助手（ProcurementAnalysis）服务器报错，恢复服务。

### 二、财务部工具交付与优化

**退税审单（Tax_check）**：已打包交付运营，实现 PDF/图片 OCR 识别 + 关键字段高亮标记，进入测试阶段。覆盖 16+ 类单据自动识别与齐全性校验；8/3 完成 OCR 自动重命名与接口重构。本周同步响应税务会计胡泳仪反馈的多类文件识别问题（货代账单误识别为合同、三方协议场景归因不准、港杂费/报关费发票误报缺失、监管仓库运输方式下出口版保税核注清单未识别），确认为程序识别错误，已列入修复清单。状态：P0 资料齐全性 + P1 OCR 识别完成，P2 LLM 智能审核阶段待规划。

**数据脱敏工具（Data_masking）**：v1.2.0 发布并交付财务部韦妹琴，从归档重新激活为长期优化项目。本次新增多工作表检测、表头自动检测、跨文件确定性脱敏（同原值跨文件得同一假值，支撑财务跨表对账）、「金额(保留格式)」脱敏方法等 9 项优化，并修复空单元格变 "nan"、遮蔽类还原串档等问题；已说明后续需增加后台监控等功能。

**开票明细追加工具**：已完成并交付，财务开票数据一键追加到总台账。新版为纯静态 HTML 工具（SheetJS），确定性执行、零安装，解决旧版 AI Skill 路线输出不稳定的问题，按发票号分组、序号续编、日期双格式等规则自动追加。

## 个人成长与思考 · 建议

- **「轻量迁移」是好方案的分水岭**：培训助手从「全量迁出」收敛到「后台不动、仅 Bot 独立 + 选修 UI 重设计」，靠的是和培训主管把量率分流、清零重置、course_type 前置等边界一条条对齐。体会：供应商系统迁移，先砍范围再谈实现，能省下大量改造量与返工；建议把「能不迁就不迁、能独立就独立」作为平台类需求的第一原则。
- **Excel 精算场景别走 AI 路线**：开票明细工具从 AI Skill 改纯静态 HTML 的教训本周仍在延续（数据脱敏、退税审单同样走本地/纯程序）。建议：凡涉及财务精确数据、要求零偏差的场景，一律优先确定性程序，AI 只做辅助识别，不做主链路计算。
- **验收要有「实锤」**：宏昊AI助手漏召问题这次带了 top-10 引用相似度（53–56% 全无关）作为证据，供应商无法用「已优化」糊弄。建议：平台类验收每次留截图/引用证据，形成可复测基线，避免口头扯皮。
- **Skill 化是需求响应的最优解**：github-kb-sync、知识库管理 Skill 本质是把重复动作固化成可复用零件。邓楚羿要求每周 2 个 Skill，方向契合「先攒零件再拼工作流」的路线；建议把各部门高频重复动作持续沉淀为 Skill，减少一次性开发。
