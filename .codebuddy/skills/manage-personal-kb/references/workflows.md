# 个人知识库操作工作流

## 目录

1. 接入检查
2. 检索与回答
3. 用知识库完成任务
4. 快速记录
5. 建立或更新项目
6. 整理成知识笔记
7. 整理最近一周
8. 归档、移动、合并或重命名
9. 现有知识库兼容调用
10. 完成报告

## 1. 接入检查

1. 按`tool-compatibility.md`识别宿主软件和实际能力。
2. 确认用户明确提供或已经授权的知识库根目录。
3. 不扫描整块磁盘寻找知识库。
4. 检查`首页.md`、AI协作约定、项目索引和知识索引。
5. 读取存在的兼容说明。
6. 读取当前任务目录，不把它误认为知识库根目录。
7. 确认当前权限是只读、计划确认还是可执行。
8. 缺少关键入口时保持只读，报告缺失内容并建议使用初始化与规范化指令。
9. 当前Agent不能读取本地文件时停止，不要求用户假装已经调用知识库。

## 2. 检索与回答

适用于“查一下”“结合知识库”“参考以前经验”等请求。

1. 从首页、知识索引和项目索引提取候选笔记。
2. 根据关键词、同义词、项目名和岗位术语搜索文件名、标签和正文。
3. 首次读取不超过约8篇高相关笔记；证据不足再扩展。
4. 先使用正式知识和当前项目，再按需扩展到每日记录、资料摘录、AI草稿和归档。
5. 对资料摘录、AI草稿和归档使用明确的层级表述。
6. 来源冲突时列出差异、日期和适用场景。
7. 输出工作结论和实际来源。

禁止：

- 为了显得有依据而列出未实际读取的笔记。
- 把AI草稿描述为本人确认结论。
- 把资料观点直接表述为已核验事实。

## 3. 用知识库完成任务

适用于方案、总结、分析、提案、培训内容、故障排查等真实工作。

1. 确认项目工作目录。
2. 对齐任务材料、预期成果、使用对象和合格标准。
3. 检索知识库中的相关规则、标准、方法和项目上下文。
4. 在开始生成前，向用户说明准备使用的知识及来源位置。
5. 生成第一版并保存到项目工作目录。
6. 说明实际使用的知识。
7. 接收人的判断和修改要求，另存新版本。
8. 达到合格可用标准后结束迭代。
9. 识别可能值得沉淀的方法，但只提出建议，不自动写回。

## 4. 快速记录

### “记一下”

1. 确认记录日期。
2. 按本地规则写入`01-每日记录/YYYY-MM-DD.md`。
3. 保留用户原意，不为了统一文风而重写个人观点。
4. 信息归属不明确时标记为待整理。

### “加入收件箱”

1. 写入`00-收件箱`中的既定入口。
2. 记录来源或上下文。
3. 不自动判断为项目或正式知识。

如果本地规则要求写入前确认，先展示目标位置和拟写内容。

## 5. 建立或更新项目

### 建立项目

1. 确认项目名称、目标、完成标准和当前状态。
2. 搜索是否已有同一项目或高度相关笔记。
3. 首次优先建立一篇项目笔记，不创建大量子目录。
4. 记录下一步、决策、风险、相关知识和材料位置。
5. 更新项目索引。

### 更新项目

1. 读取现有项目笔记。
2. 区分新事实、决定、行动、风险和待确认事项。
3. 展示拟更新位置和内容。
4. 确认后更新`updated`日期和正文。
5. 不把项目交付成果全文复制进知识库。

## 6. 整理成知识笔记

1. 确认来源名称、位置、日期和授权边界。
2. 搜索相近知识，判断更新、拆分、合并或新建。
3. 首次最多提出5篇候选笔记。
4. 每篇候选说明：
   - 建议标题
   - 解决的问题
   - 核心内容
   - 来源
   - 建议位置
   - 与已有笔记的关系
5. 区分：
   - 资料摘录
   - AI草稿
   - 项目内容
   - 正式知识
6. 等待本人确认后写入。
7. 写入后更新知识索引和相关双向链接。
8. 输出实际新增、更新或跳过的文件。

## 7. 整理最近一周

1. 读取最近7天每日记录和当前收件箱。
2. 对照项目索引识别进展、决策、阻碍和下一步。
3. 对照知识索引识别可复用方法和可能重复内容。
4. 输出建议清单：
   - 更新项目
   - 新增或更新知识
   - 继续留在收件箱
   - 建议归档
5. 未确认前不批量写入或移动。
6. 用户确认具体范围后分项执行。

## 8. 归档、移动、合并或重命名

1. 列出准确源路径和目标路径。
2. 检查同名冲突、Obsidian链接和外部引用。
3. 展示影响和无法确认的风险。
4. 等待本人明确确认。
5. 只执行批准清单。
6. 不直接删除正式笔记。
7. 移动或重命名后验证目标文件、索引和链接。
8. 合并时保留来源和未确认差异，不静默丢弃内容。

## 9. 现有知识库兼容调用

存在`90-系统模板/现有知识库兼容说明.md`时：

1. 读取旧目录到新规范的映射。
2. 检索时同时覆盖标准目录和已登记旧目录。
3. 旧内容的可信度按兼容说明和实际位置判断。
4. 不因为已建立新架构就忽略旧知识。
5. 不在普通调用中自动完成历史迁移。
6. 发现映射失效或新目录时，提出更新兼容说明的建议。

## 10. 完成报告

只读调用：

```text
知识库调用：轻量/深度｜使用笔记：N篇

实际使用：
- 文件路径

未找到、冲突或待核验：
- 问题
```

写入操作：

```text
已新增：
- 文件路径

已更新：
- 文件路径

已移动或归档：
- 原位置 → 新位置

已跳过：
- 文件路径｜原因

待本人判断：
- 问题
```
