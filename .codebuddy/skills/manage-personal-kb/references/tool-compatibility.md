## 1. 检测原则

先识别宿主软件，再识别实际能力。产品名称只用于选择适配入口，实际权限和工具能力决定能否执行。

检测优先级：

1. 系统提供的宿主产品元数据。
2. 用户明确说明的软件名称和版本。
3. 当前工作区中可验证的产品配置。
4. 当前会话实际可调用的工具和权限。
5. 无法确认时进入通用兼容模式。

不得根据以下信息单独判断宿主软件：

- 当前使用的模型名称
- 对话语言
- 某一个可疑目录
- AI自称的软件名称

WorkBuddy等软件可以切换不同模型；模型供应商不等于宿主软件。

## 2. 能力画像

首次调用时形成以下临时画像，不自动写入知识库：

| 项目 | 可选状态 |
|---|---|
| 宿主软件 | Codex／WorkBuddy／MiniMax Code／TRAE／其它Agent／无法确认 |
| 软件版本 | 已确认／未提供 |
| Skill形态 | 原生Skill／项目规则／长期指令／会话附件／无法加载 |
| 本地文件读取 | 可用／需授权／不可用 |
| 本地文件写入 | 可用／需确认／只读／不可用 |
| 工作空间 | 已设置／未设置／无法确认 |
| 多目录访问 | 可用／需分别授权／不可用／无法确认 |
| 持久规则或记忆 | 可用／不可用／无法确认 |
| 当前执行权限 | 只读／计划确认／可执行／无法确认 |

只在需要写入时进行最小能力测试。测试前说明准备创建或修改的测试文件，并取得本人确认。不得为了识别软件在知识库中留下无用途文件。

## 3. Codex

已确认环境为Codex，且Skill已被加载时：

1. 将本文件夹作为原生Skill运行。
2. 使用系统提供的当前工作目录和授权范围。
3. 如果知识库不在当前工作目录中，请用户明确提供并授权知识库路径。
4. 不因为Skill被加载就自动获得知识库或项目目录权限。
5. 按知识库本地规则决定写入确认方式。

无法确认Skill已加载时，不声称当前运行的是原生Skill。

官方参考：

- OpenAI Skills支持ChatGPT、Codex和API。
- `SKILL.md`是Skill的工作流程入口。

## 4. WorkBuddy

已确认环境为WorkBuddy时：

1. 优先检查本Skill是否通过本地Skill包导入并处于启用状态。
2. 确认当前工作空间是否为知识库目录、项目目录，或是否已分别授权两者。
3. 识别当前工作模式：
   - Ask：按只读处理，不修改文件。
   - Plan：先展示计划和文件范围，确认后执行。
   - Craft：具备修改能力时仍遵守知识库本地确认规则。
4. 本地Skill未成功导入时，将`SKILL.md`及其references作为项目长期指令或会话附件加载，并标注“等效能力”。
5. WorkBuddy可能使用MiniMax、GLM、Kimi、DeepSeek或混元等模型；不能据此改变宿主判断。

官方资料确认WorkBuddy支持本地Skill包导入、本地文件工作空间以及Ask、Plan、Craft模式。实际界面和权限以当前版本为准。

## 5. MiniMax Code

已确认环境为MiniMax Code时：

1. 确认当前工作空间已经选择并允许读取本地文件。
2. 检查当前版本是否提供Skill安装、创建或选择入口。
3. 官方资料确认MiniMax Code提供工作空间、本地文件、Skill和持久记忆能力，但未在本Skill中预设其本地Skill包目录或文件格式。
4. 未验证当前版本能够原生导入本文件夹时：
   - 不声称安装成功；
   - 优先把本Skill作为项目长期指令或会话附件；
   - 标注为“等效能力”。
5. 如果产品已经成功识别并调用本Skill，记录为原生Skill；否则按实际能力降级。

## 6. TRAE

已确认环境为TRAE时：

1. 检查当前版本是否支持Agent Skills。
2. 项目级Skill优先放在当前项目的`.trae/skills/manage-personal-kb/`中。
3. 用户级Skill位置可能因国际版和中国版不同，应以当前版本帮助页面或设置界面为准。
4. 检查项目规则、用户规则或自定义Agent是否对文件写入和输出方式有额外限制。
5. 仅发现`.trae`目录不能证明当前会话一定运行于TRAE；仍需结合宿主信息或用户确认。
6. 无法确认当前版本原生加载时，使用项目规则或会话附件并标注“等效能力”。

## 7. 其它Agent

无法识别或不属于以上产品时，按能力而不是品牌选择运行方式：

### A. 原生Skill型

- 能加载包含`SKILL.md`的Skill文件夹。
- 直接安装本Skill并验证是否被触发。

### B. 项目规则型

- 不能安装Skill，但支持项目长期规则。
- 将`SKILL.md`核心行为加载为项目规则，并确保references可访问。
- 标注“等效能力”。

### C. 长期指令或记忆型

- 支持工作空间长期指令或持久记忆。
- 加载核心行为，但不要把知识库正文全部写入记忆。
- 标注“等效能力”。

### D. 会话附件型

- 只能读取当前对话附件。
- 每次新会话重新提供Skill文件夹或必要文件。
- 无法保证跨会话自动调用，必须明确说明。

### E. 纯对话型

- 不能读取本地文件。
- 不执行知识库管理或检索；说明当前只能处理用户粘贴的内容。

## 8. 降级策略

按以下顺序选择可用形态：

`原生Skill → 项目规则 → 长期指令 → 会话附件 → 停止本地知识库操作`

降级时保持相同的知识分类、安全边界、写入确认和来源输出要求。

如果只能访问一个目录：

- 只读检索可以在知识库目录中执行。
- 完成真实任务时，要求用户在当前工具中分别授权知识库与项目目录；无法做到时，先把任务材料放在已授权项目空间，并以只读附件方式提供必要知识。
- 不建议为了工具限制把全部项目材料复制进个人知识库。

## 9. 检测输出

首次调用时简要报告：

```text
Agent环境：
- 宿主软件：
- 版本：
- Skill运行形态：原生Skill／等效能力
- 知识库目录：
- 项目目录：
- 文件权限：只读／计划确认／可执行
- 多目录访问：
- 当前限制：
```

不要每轮重复输出完整画像；只有环境、目录或权限发生变化时重新确认。
