# 知识库录入 Skill（kb-ingest）

## 何时使用
用户说"去 raw 提取 / 整理 raw / 把 raw 里的整理进 wiki / 录入 / 写进知识库"等，且 `raw/未处理/` 有待处理文件时，先完整阅读本文件，再开始操作。

## 知识库现状（e:/lw，截至 2026-07）
- `raw/未处理/`：收件箱，用户不断往这里丢原始素材（周报、测评、读书记录、项目资料…），待 AI 提取。
- `raw/已处理/`：AI 提取知识后把源文件移入此处，保留溯源，避免重复提取。
- `wiki/日记/`：按时间类型拆分 `日报/`、`周报/`、`月报/`、`随笔/`
- `wiki/读书笔记/`：按书分册（已建 `干出好结果.md`、`干得漂亮.md`、`赢利.md`、`赢销铁军.md`、`高效能人士的七个习惯.md`）
- `wiki/个人档案/`：自我认知类（如 `肖聪-职场风格测评-2026-04.md`）
- `wiki/项目/`、`wiki/领域/`、`wiki/灵感/`（注意：`灵感/` 与 `日记/随笔/` 功能重叠，录入前先和用户确认放哪，避免重复分类）
- 门户：`欢迎.md`（手写链接导航）；模板：`Templates/`

## 录入 SOP（必须按序执行）
1. **扫描 `raw/未处理/` 全部文件**：批量处理，不遗漏；不处理 `raw/已处理/` 里的文件。
2. **识别文件类型 → 建议归入目录**（仅建议，需用户确认，不擅自新建分类）：
   - 周报 / 月报 → `wiki/日记/周报/` 或 `月报/`
   - 日报 → `wiki/日记/日报/`
   - 读书分享 → `wiki/读书笔记/<书名>.md`（按书分册，不混册）
   - 测评 / 自我认知 → `wiki/个人档案/`
   - 零散想法 → `wiki/日记/随笔/` 或 `wiki/灵感/`（二选一并确认）
3. **反问只在歧义时**（不要每步都问）：当分类不清、字段歧义、是否关联真实条目等拿不准时才问用户；规则明确的直接按前置约定执行。前置约定（已确认，勿再追问）：
   - 载体工具 Obsidian → 可用 `[[wikilink]]` 双链 + `---` frontmatter
   - 时间粒度：只到**年月日**
   - 岗位：统一 **AI 技术专员**（早期"总经办助理"在录入时替换）
   - 字段名忠实原文（如"过往错点"不要改成"反思 / 过往错点"）
   - 读书笔记不关联周报/日报
4. **一致性检查**：录入前先读目标目录现有文件与索引，对齐命名约定（如周报 `周报-4.13-4.19.md`、读书笔记 `## 2026-05-11 · 第X章` 标题风格），避免风格漂移。
5. **执行录入**：忠实原文，仅修正明显语音/输入错字；按归类写入 `wiki/`。
6. **移入 `raw/已处理/`**：本文件对应的源文件提取完成后，移入 `raw/已处理/`（保留溯源，避免重复提取）。
7. **回执**：明确告诉用户——从 raw 提取了哪些、落在哪个 `wiki/` 路径、已移入已处理哪些、有哪些假设需要他确认。

## 禁忌（已踩过的坑，禁止再犯）
- ❌ 擅自把内容重排成"标准模板"（除非用户明确要求）
- ❌ 臆测关联项目 / 笔记，尤其链接不活跃或不存在的条目（前车之鉴：误链 MKtech、LabEqManager、sparkcanvas 被纠正）
- ❌ 默认 Obsidian 双链语法而不先确认载体工具（现已确认 Obsidian，除非用户改口不再问）
- ❌ 改动用户原始字段名
- ❌ 在顶层反复新建重复分类（如 `灵感/` 与 `随笔/` 并存却不区分）
- ❌ 过度建索引：保持 `欢迎.md` + 必要索引即可，不必每类都建 `索引.md`
- ❌ 提取后未将源文件移入 `raw/已处理/`，或把已处理文件丢回 `未处理/`

## 反问问题模板（仅在歧义时使用 ask_followup_question 或对话提问）
- "这份内容归 `wiki/日记/随笔/` 还是 `wiki/灵感/`？（两者功能重叠）"
- "这个字段原文有歧义，按 X 理解可以吗？"
- "要关联哪些已有的笔记 / 项目？请给确切名称（我不会自己猜）。"

- 录入后如需反向在周报 / 项目笔记加链接，同样要先确认目标存在。
