# 知识库录入 Skill（kb-ingest）

## 何时使用
用户说"整理 / 归档 / 收录 / 录入 / 写进知识库"某文件或内容时，先完整阅读本文件，再开始操作。

## 知识库现状（e:/lw，截至 2026-07）
- `wiki/日记/`：按时间类型拆分 `日报/`、`周报/`、`月报/`、`随笔/`
- `wiki/读书笔记/`：按书分册（已建 `干出好结果.md`、`干得漂亮.md`、`赢利.md`）
- `wiki/个人档案/`：自我认知类（如 `肖聪-职场风格测评-2026-04.md`）
- `wiki/项目/`、`wiki/领域/`、`wiki/灵感/`（注意：`灵感/` 与 `日记/随笔/` 功能重叠，录入前先和用户确认放哪，避免重复分类）
- 门户：`欢迎.md`（手写链接导航）；原始素材：`raw/`

## 录入 SOP（必须按序执行）
1. **确认载体工具**（最关键，先问）：用户用什么看知识库？
   - Obsidian → 可用 `[[wikilink]]` 双链 + `---` frontmatter
   - Typora / VS Code / 其他 → **不用双链语法**，用普通标题与路径，frontmatter 也省略或简化
2. **识别文件类型 → 建议归入目录**（仅建议，需用户确认，不擅自新建分类）：
   - 周报 / 月报 → `wiki/日记/周报/` 或 `月报/`
   - 日报 → `wiki/日记/日报/`
   - 读书分享 → `wiki/读书笔记/<书名>.md`（按书分册，不混册）
   - 测评 / 自我认知 → `wiki/个人档案/`
   - 零散想法 → `wiki/日记/随笔/` 或 `wiki/灵感/`（二选一并确认）
3. **反问澄清（不要臆测，至少确认以下项）**：
   - 这份内容要不要按模板重排，还是**原样保留**？
   - 需要关联哪些**真实存在且用户认可**的笔记 / 项目？（绝不可自行编造，或链接不活跃 / 不存在的条目——前车之鉴：误链 MKtech、LabEqManager、sparkcanvas 被纠正）
   - 时间粒度：只到**年月日**，还是带时分？（用户偏好：只到年月日）
   - 字段名是否**忠实原始表头**（如"过往错点"不要擅自改成"反思 / 过往错点"）
4. **一致性检查**：录入前先读目标目录现有文件与索引，对齐命名约定（如周报 `周报-4.13-4.19.md`、读书笔记 `## 2026-05-11 · 第X章` 标题风格），避免风格漂移。
5. **执行录入**：忠实原文，仅修正明显语音/输入错字；按用户确认结果决定是否重排、是否加链接。
6. **回执**：明确告诉用户——做了什么、放在哪个路径、有哪些假设需要他确认。

## 禁忌（已踩过的坑，禁止再犯）
- ❌ 擅自把内容重排成"标准模板"（除非用户明确要求）
- ❌ 臆测关联项目 / 笔记，尤其链接不活跃或不存在的条目
- ❌ 默认 Obsidian 双链语法而不先确认载体工具
- ❌ 改动用户原始字段名
- ❌ 在顶层反复新建重复分类（如 `灵感/` 与 `随笔/` 并存却不区分）
- ❌ 过度建索引：保持 `欢迎.md` + 必要索引即可，不必每类都建 `索引.md`

## 反问问题模板（可用 ask_followup_question 或对话提问）
- "你看知识库用的是 Obsidian，还是 Typora / VS Code 之类？"
- "这份内容想原样留存，还是按模板整理一遍？"
- "要关联哪些已有的笔记 / 项目？请给确切名称（我不会自己猜）。"
- "时间只写到年月日可以吗？"
