# 智能体验收方法论

> 基于宏昊AI助手平台 2604–2607 四个验收批次（约 40+ 用例）的实战经验提炼。

## 一句话说明

如何在供应商交付的 AI 智能体平台上做系统化验收，确保更新项真正可用。

## 核心结论

智能体验收不同于纯功能测试，关键在于**权限-知识库-智能体三者的联动验证**。最常见的漏测点不在功能本身，而在**权限继承、跨模块关联、边界条件**。

## 验收维度

### 1. 权限层（最先验）

验证三层权限是否隔离正确：

| 场景               | 验证要点                                      |
| ---------------- | ----------------------------------------- |
| 无智能体权限           | 无法进入对话，连入口都看不到                            |
| 有智能体权限但无知识库权限    | 能对话但不能引用内部文档，不返回文档链接                      |
| 有智能体权限 + 部分知识库权限 | 仅能引用已授权知识库，未授权知识库完全隔离                     |
| 部门授权继承           | 父级部门授权 → 子部门用户继承；新增子部门 → 自动继承；人员调动 → 权限随动 |
| 权限覆盖与冲突          | 子部门独立授权不反向影响父级；父级授权不覆盖子部门独立授权             |

**关键教训**：260608 批次中"有智能体权限+部分知识库权限"场景未通过——说明书助手虽有智能体查看权限但无法正确引用部分关联知识库。这说明**权限-知识库联动的边界条件**是最容易出问题的地方。

### 2. 功能层（按更新清单逐项验）

- 每项更新都要有**原行为 vs 新行为**的对比基线
- 关注"新增功能是否破坏了旧功能"——供应商常在新功能迭代中引入回归问题
- 典型遗漏：**错误提示**（如试题生成失败无提示，260707 才补齐）

### 3. 数据层

- **报表/统计**：字段是否完整、数据是否准确（260702 培训报表字段不全、学员端看板统计数据有误）
- **分页/性能**：大数据量下的翻页和加载（260701 知识库新增 20条/页分页）
- **编码/冲突**：目录编码重复时的提示和处理

### 4. 终端兼容层

- **iOS/移动端**：企业微信内嵌页面在企业微信 iOS 端的表现（260710 水印修复）
- **Win7 兼容**：桌面端应用是否适配旧系统（简历抓取因 Win7 缺 dll 无法打开）

## 验收流程建议

```
收到更新清单 → 逐项确认原行为基线 → 制定测试用例（覆盖权限/功能/数据/终端四层）
  → 执行验收 → 标记通过/不通过 + 实际结果截图 → 汇总问题反馈
  → 跟进修复 → 复验 → 闭环
```

## 使用场景

- 供应商交付 AI 平台更新后的验收
- 内部自研 AI 工具上线前的质量检查
- 跨部门 AI 工具推广前的功能验证

## 判断标准

- 通过：实际结果 = 预期结果，且无回归
- 不通过但有 workaround：记录 workaround，标记待修复
- 完全不通过：阻塞上线，要求供应商修复后复验

## 适用边界

- 适用于「供应商交付 → 内部验收」模式
- 不适用于自研项目的持续集成测试（自研更适合自动化测试）
- 权限继承逻辑适用于 RBAC/ReBAC 模型，不适用于简单的角色-权限一一对应
