## 一、会议概述

本周 AI 小组（3 人：邓楚羿主管 / 肖聪技术 / 刘妍妍运营）复盘各项目进度，并集中暴露两类管理问题：**①过程汇报脱节**（关键沟通只在私聊、带教无中间反馈）；**②需求收集机制不清**（业务方数据 / 规则不先梳理、AI 小组被动追问擦屁股）。会议明确：下周起按业务价值（PBC 应用价值验证）排优先级推进跨部门需求，并落地"需求方先填预收集表、数据规则自行理清再交"的机制。

**一句话主线：** 从"各做各的进度"转向"过程可追踪 + 需求可筛选 + 价值可排序"——先把协同机制立起来，再按价值高低打跨部门需求。

## 三、重点决议

### 3.1 过程管理整改（汇报机制）
- **问题**：培训助手下周一测试仅私聊确认，信息脱节；带教协助同事做财务对账无中间反馈，主管不知情。
- **决议**：
  1. 关键节点沟通必须落到群里，或专门向主管汇报，杜绝"只有你知道"；
  2. 任意小项目立"项"要有目标 / 计划 / 节点反馈，每周至少一次进展同步；
  3. 跨节点超期必须反馈，便于协调资源——不能等到周五周会才暴露。

### 3.2 需求收集机制（重点）
- **决议**：
  1. 需求先填**预收集表**做初步价值判断，不直达 P2P 追问；对方不填则先搁置（除非高价值）；
  2. **业务数据与规则先由需求方自行梳理清楚再交 AI 小组**，否则"不整理好就不做"——禁止 AI 小组替业务擦屁股、被动追问；
  3. 需求登记表内容因复制换行丢失，需补全（雪莹姐条）；
  4. 客服路线需求（吴秀红）有"留存经验"价值，由邓楚羿带刘妍妍专项约谈吴秀红 + 清姐。

### 3.3 业务优先级与精力分配
- **肖聪精力**：业务陪练（语音 + TT）功能闭环即停，不过度投入；TT / 清关材料耗时大，开发时间与 skill 化时间要配比，避免单点钻深影响绩效广度。
- **跨部门需求**：下周继续调研，按 PBC 应用价值验证排优先级，优先高价值场景。
- **采购（雪莹姐）**：在现有 skill 基础上完善，整合网站 + 公众号信息，输出趋势分析并推送到群（群内含老板 / 梅姐 / 研发经理）；可教其用 bot 自动向供应商发询价。
- **船务**：TT （清关材料）最刚需，但开发量大，至多实现一个（信息识别 → 自动发送），不全做。
- **方总 / 胡总**：胡总想约方总聊供应商；方总倾向更短路径 / 现成方案，优先用现成。

### 3.4 培训安排
- WorkBuddy 培训主题定为"**AI 自动化**"，双线：主线 = WorkBuddy（肖聪日常写周报 / 日报示范）；次线 = 大模型自动化（定期汇报 / 信息抓取总结，如雪莹姐每日查漏）。思路通用，可迁移其他 AI。
- 周报要基于每日总结 + 仓库内容用代理生成；培训前先写文档 / 讲义自看，不依赖 AI 生成 PPT，需先演示捋顺。
- 知识库迁移**分批**推进（A/B 组 + 研发部等），研发部先与领导沟通；人事上传的视频 / 照片需确认使用范围（活动类全公司开放）。

### 3.5 公共知识库
- 培训资料暂不需传公共知识库（各部门自管，文婷姐管控），后续确认迁移或另存。
- 跨部门沟通用问卷，不填则电话跟进。
