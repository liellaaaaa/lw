# Tax_check · 退税资料智能审核助手（P0 原型）

## 项目简介

为**外贸出口退税**场景做的资料审核工具原型（PRD：《退税资料智能审核助手需求文档》，作者刘妍妍，2026-06-27，业务方为**宏昊化工**等化工出口企业）。出口退税对资料完整性要求极高——退税资料缺失会直接导致退税失败、税款无法退回。

本仓库实现的是 **P0：资料齐全性审核**（文件级体检）：
- 按文件名关键词识别**单据类型**（目前覆盖 16+ 种：PI、合同、提单、发票、装箱单、报关单、申报要素、境货/离境货物报关单、退税申报明细、外汇/收汇、保险、运费/海运费、内陆运、装港/起运港、备注等）
- 依据**价格条款矩阵**（EXW/FOB/C&F/CIF）判断是否需要对应运费发票，校验「是否缺运费发票」
- 校验拖车/运输条件、必传单据是否齐全
- 支持**重命名、确认、导出 ZIP**

设计原则强调**数据不出境 / 本地部署**：P0 完全在浏览器端运行，不上传任何文件。P1（OCR 结构化识别，如报关单/发票字段抽取）与 P2（LLM 智能审核与问答）为后续阶段。

## 技术栈

- 纯前端、**零依赖构建**：原生 **JavaScript** + HTML + CSS
- **JSZip**：浏览器端打包导出 ZIP
- 浏览器 **File API / File System Access API**：本地文件夹导入、重命名、导出（数据不出浏览器）
- 无后端、无框架、无打包工具（直接打开 `detect.html` 即可运行）

## 系统架构

```
浏览器端（detect.html）：
  选择文件夹 → 读取文件(文件名) → 关键词匹配分类单据类型
            → 价格条款矩阵判定必需运费发票 → 齐全性校验
            → 用户确认/重命名 → JSZip 导出 ZIP
```
- 完全本地：文件不上传服务器，满足「数据不出境」合规要求
- 关键词匹配 + 规则矩阵，不依赖 OCR/LLM（P0 阶段）

## 数据模型

- 输入：`退税资料` 文件夹（一批单据文件）
- 单据类型（关键词识别，示例）：
  - PI / 合同 / 提单(B/L) / 发票 / 装箱单 / 报关单 / 申报要素
  - 境货报关单 / 离境货物报关单 / 退税申报明细
  - 外汇 / 收汇 / 保险 / 海运费 / 内陆运 / 装港 / 起运港 / 备注
- 价格条款矩阵：EXW / FOB / C&F / CIF → 决定是否需要运费发票

## 核心功能模块（workspace/tax-refund-audit-prototype）

- **detect.html**：页面入口（导入、分类展示、校验结果、导出）
- **app.js**：核心逻辑——文件夹导入、文件名关键词→单据类型映射、价格条款矩阵判定、齐全性校验、重命名、确认、JSZip 导出
- **style.css**：样式

## 亮点 / 可复盘点

- **零依赖纯静态**，双击即跑，部署成本极低
- 严格的「数据不出境」：纯浏览器端，适合合规敏感的外贸企业
- 用「文件名关键词 + 价格条款矩阵」做资料齐全性体检，思路可直接复用于其它单证审核场景
- PRD 完整（含定位、价值、用户流程、功能清单、技术约束），是「需求→原型」的好样本

## 需注意的已知问题

- P0 仅文件级审核，**不解析单据内容**（无 OCR），无法校验单据内部字段一致性
- 关键词匹配对文件名规范依赖强，命名不规范的单据易误判/漏判
- P1（OCR）/ P2（LLM）尚未实现，复杂审核仍需人工
- 大文件夹（上千文件）下纯前端遍历性能需实测
