工作框架总览

INTERNAL / EXTERNAL

内部（公司内）

  1. 需求研判 · 方案设计 · 跨部门对接——从"接需求"前移为"判需求、出方案、对接领导拍板、推动执行与迁移"。
  2. 自研应用交付（建应用路径）——客户端/前端/前后端：船务 T/T 助手、采购分析、对账单、退税审单、数据脱敏。
  3. Skill 抽象与复用（提效路径）——复现场景、抽象输入输出为可复用 Skill，提效或赋能业务自建。
  4. 培训与推广——技术（编程/前后端/Skill）+ 非技术（WorkBuddy/千问/读书）；含采纳驱动与宣推。

外部（供应商）

  1. 找供应商实现固定需求（线索获取等）——非重点，不展开。
  2. 宏昊 AI 助手平台（供应商）——验收运营与质量闭环、知识库内容运营监督、权限与文档管理中心、各智能体、培训助手、内容生成助手（视频/图片）。
岗位本质：AI 技术专员 = 出方案 / 判断方案 / 对接领导一键 / 推动执行与迁移，不是运营。本报告据此把"方案设计、验收监督、推广采纳"单列，不被"执行"吞没。

① tax-refund-audit

  • 交付对象：财务部
  • 形态：可复用 Skill（退税审单工作流抽象）
  • 与 Tax_check 应用互补——应用做"体检"，Skill 做流程复用下沉
  • ✅ 已交付财务使用

价值：高频强规则工作流抽象为 Skill，财务直接复用，降低对专人/专工具依赖——"工具 + 技能"双交付。

② daily-commodity-price-scraper

  • 定位：钩子（hook）——培养采购部门自主制作 Skill
  • 交付对象：采购部（赋能，非代劳）
  • 后续仍回采购培训，巩固"自建 Skill"能力
  • 理念：复现场景 → 抽象复用 → 赋能业务自建

价值：以价格爬取 Skill 为教具让采购部学会自己造 Skill，把提效能力留在业务侧。
