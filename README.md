# 个人知识库（Personal Knowledge Base）

> 管理者：肖聪（AI 技术专员） · 载体：Obsidian · 根目录：`e:/lw`

## 1. 这是什么

一个以**个人成长**为核心的长期知识库。把日常工作记录、读书思考、项目经验、自我认知沉淀为可检索、可复盘的"个人资产"。不对外发布，主要服务本人复盘与 AI 辅助整理。

## 2. 工作流（怎么运转）

1. **你（用户）**：把任何原始素材（周报、测评、读书记录、项目资料…）丢进 `raw/未处理/`，不断累积。
2. **AI 助手**：你定期说"去 raw 提取"，AI 扫描 `raw/未处理/` 全部文件，提炼知识存入 `wiki/` 对应分类，再把源文件移入 `raw/已处理/`。
3. **你查看**：在 Obsidian 里通过 `欢迎.md` 门户浏览 `wiki/` 已整理内容。

原始文件始终保留（未处理 → 已处理），`wiki/` 是提炼后的结构化知识，二者分离、可溯源。

## 3. 适用对象

- **本人**：日常记录、复盘、读书分享、沉淀方法论。
- **AI 助手**：按 [`AGENTS.md`](AGENTS.md) 与 `.codebuddy/skills/kb-ingest` 规范，从 `raw/未处理/` 提取并整理。

## 6. 工具依赖

## 7. 如何"去 raw 提取"（AI 操作）

当你叫 AI 整理 `raw/` 时，遵循 `.codebuddy/skills/kb-ingest` 规范，流程为：

1. **扫描** `raw/未处理/` 全部文件 → 2. **识别类型、建议归入 `wiki/` 目录** →
3. **歧义才反问**（分类不清 / 字段歧义 / 是否关联）→
4. **对齐目标目录现有格式并写入** → 5. **源文件移入 `raw/已处理/`** → 6. **回执**。

智能体层面的硬约束见 [`AGENTS.md`](AGENTS.md)。

### 已确认的统一约定
- 时间只写**年月日**，不写时分。
- 岗位统一写 **AI 技术专员**。
- 读书笔记字段：`个人收获 / 过往错点 / 今后改进`。
- 读书笔记**不**反向链接周报 / 日报（2026-07 起取消）。
- `raw/` 机制：未处理 →（AI 提取）→ 已处理，原始文件不删除。

## 8. 维护约定

- **索引手写维护**：`欢迎.md` 与各 `索引.md` 由人工 / AI 在新增内容后同步更新，保持入口可达。
- **命名一致**：周报 `周报-M.D-D.M.md`、日报 `日报-YYYY-MM-DD.md`、读书笔记 `书名.md`、项目 `仓库名.md`。
- **raw 机制**：你只往 `raw/未处理/` 丢文件；AI 提取后自动移入 `raw/已处理/`；不要在 `wiki/` 直接堆原始文件。
- **不重复提取**：已处理文件留在 `raw/已处理/`，不要再次丢回 `未处理/`。
